# 아주 전략적인 체스 (Very Tactical Chess) — 스펙

## Problem Statement

일반 체스는 정해진 규칙 안에서만 기물을 움직일 수 있다. 친구와 체스를 두면서 "폰을 나이트에 태워서 돌진시킨다", "비숍이 성벽을 세운다" 같은 상상력을 발휘하고 싶어도, 그걸 공정하게 판정해 줄 사람이 없다. 사람이 GM을 맡으면 한 명은 플레이할 수 없고, 판정이 편향되거나 매번 달라진다. 또 이런 게임을 친구와 온라인으로 즐기려면 서버 비용이 드는데, 취미 프로젝트로는 감당하기 어렵다.

## Solution

두 플레이어가 각자 브라우저에서 접속해 체스를 두되, 규칙에 없는 기상천외한 행동을 채팅으로 입력하면 LLM GM이 판정해 주는 TRPG형 체스 게임이다.

- 정상적인 체스 수는 게임 엔진이 즉시 처리한다.
- 규칙 밖의 행동은 "특수 행동"으로 LLM GM에게 전달된다. GM이 해석, 난이도(DC), 비용(AP)을 제시하면, 플레이어가 시도 여부를 정하고 6면 주사위(d6)로 성패가 갈린다.
- 결과는 엔진이 검증 가능한 정해진 효과(이동, 제거, 태그 부여, 변환, 생성, 편 바꾸기, 맞바꾸기, 되살리기, 지형)로만 보드에 반영되어 보드 상태가 흔들리지 않는다.
- 킹을 잡으면 승리한다. 원턴킬 방지 규칙으로 특수 행동을 이용한 즉사 콤보를 막는다.
- 체스판, 기물, 주사위는 3D로 표현하고, 주사위는 실제로 구르는 연출과 함께 결과가 나온다.
- 서버 없이 P2P(방장 브라우저가 권위)로 동작하고, 정적 사이트로 무료 배포한다. LLM API 키는 방장 본인 것을 쓴다(BYOK).

## User Stories

### 방 만들기와 접속

1. As a 방장, I want 새 게임 방을 만들고 방 코드/초대 링크를 받기, so that 친구를 쉽게 초대할 수 있다
2. As a 방장, I want 방을 만들 때 GM으로 쓸 LLM 제공자(Claude, OpenAI, Gemini)와 모델을 고르기, so that 내가 가진 키와 선호에 맞출 수 있다
3. As a 방장, I want 내 API 키를 입력하기, so that 운영자 서버 없이 GM 판정을 쓸 수 있다
4. As a 방장, I want 내 API 키가 상대 브라우저로 절대 전송되지 않기, so that 키가 유출되지 않는다
5. As a 방장, I want 무료로 쓸 수 있는 키(Gemini 무료 등급) 안내를 보기, so that 비용 없이 시작할 수 있다
6. As a 참가자, I want 초대 링크나 방 코드로 방에 들어가기, so that 별도 가입 없이 바로 플레이할 수 있다
7. As a 참가자, I want 내 API 키 없이도 플레이하기, so that 방장만 키를 준비하면 된다
8. As a 플레이어, I want P2P 연결이 실패했을 때 그 사실과 대안(핫시트 모드)을 안내받기, so that 막히지 않고 게임할 수 있다
9. As a 플레이어, I want 한 화면에서 번갈아 두는 핫시트 모드로 플레이하기, so that 네트워크 문제가 있거나 옆에 앉아 있을 때도 게임할 수 있다
10. As a 플레이어, I want 내가 백인지 흑인지 명확히 알기, so that 헷갈리지 않는다

14. As a 플레이어, I want 내 킹을 공격받는 위치에 두는 수(자살 수 포함)도 둘 수 있되 경고를 보기, so that 킹 잡기 승리 규칙과 일관되면서 실수를 알아챌 수 있다

## Implementation Decisions

### 아키텍처

- **P2P, 방장 권위.** 방장 브라우저가 게임 엔진을 실행하고 보드 상태, 주사위, LLM 호출을 모두 담당한다. 참가자 브라우저는 입력을 방장에게 보내고 방장이 브로드캐스트하는 상태를 표시만 한다. 방장이 조작할 가능성은 친구끼리 플레이하는 범위에서 허용한다.
- **연결:** PeerJS의 무료 공개 시그널링 서버로 WebRTC 연결을 맺는다. 방 코드는 방장의 피어 ID에서 만든다. 연결이 실패하는 환경을 위해 같은 엔진을 쓰는 로컬 핫시트 모드를 제공한다.
- **배포:** 정적 사이트를 GitHub Pages에 무료로 배포한다. 운영 서버는 없다.
- **스택:** TypeScript, Vite, React. 3D는 react-three-fiber + drei, 주사위 물리 연출은 Rapier. 체스 로직은 직접 구현한다(chess.js 같은 라이브러리는 태그·탑승 상태를 표현할 수 없음).
- **나중의 전환:** 출시를 검토하게 되면 엔진을 서버(예: Cloudflare Workers + Durable Objects)로 옮겨 서버 권위 구조로 바꾼다. 이를 위해 엔진은 처음부터 순수 모듈로 만든다.

### 모듈

1. **게임 엔진 (핵심, 순수 모듈).** 네트워크, UI, LLM, 난수 소스에 의존하지 않는다. 인터페이스는 대략 "현재 상태 + 명령 → 새 상태 + 이벤트 목록 (또는 거부 사유)" 형태의 리듀서다.
   - 상태: 보드(칸별 기물, 기물 ID, 색, 종류, 태그 목록), 현재 턴과 턴 번호, 각 플레이어의 AP, 이번 턴 AP 사용 여부, 일반 수 사용 여부, 캐슬링·앙파상 권리, 판례 목록, 게임 종료 여부와 승자.
   - 명령: 일반 수, 특수 행동 제안 수신(GM 결과), 특수 행동 시도(주사위 값을 입력으로 받음), 특수 행동 취소, 턴 종료.
   - 주사위 값은 엔진 밖에서 생성해 명령에 담아 넘긴다. 그래야 엔진이 결정적이고 테스트 가능하다.
   - 담당 규칙: 합법 수 판정(태그 반영), 효과 검증과 적용, AP 증감과 이월, 태그 지속 시간 감소와 만료, 체크 판정, 원턴킬 방지, 자동 턴 종료, 킹 잡기 승리.
2. **효과 어휘 (엔진의 일부).** GM이 반환할 수 있는 효과는 다음으로 한정한다.
   - 이동(기물 ID, 목적지)
   - 제거(기물 ID). 대상이 킹이면 거부.
   - 태그 부여/해제(기물 ID, 태그 이름, 선택적 지속 턴 수). 지속 턴이 없으면 영구.
   - 변환(기물 ID, 새 종류)
   - 생성(칸, 색, 종류)
   - 핵심 태그는 엔진이 의미를 강제한다: `기절`(이동 불가, 체크를 걸지 못함), `탑승`(운반 기물 ID 참조, 함께 이동, 체크 판정은 운반 기물의 이동 방식), `보호막`(첫 번째 잡힘을 무효화하고 소멸), `화상`(지속 턴 안에 칸을 옮기지 않으면 타서 없어짐, 옮기면 꺼짐), `공중부양`(공중 판으로 떠오름, 끝나면 떨어짐; 아래 "공중부양"). 그 밖의 태그는 자유 태그로 엔진은 저장만 하고 GM 문맥으로 넘긴다.
3. **GM 모듈 (LLM 판정).**
   - 입력: 플레이어의 행동 선언(최대 200자), 현재 보드 상태 요약, 해당 플레이어의 AP, 판례 목록, 효과 어휘 정의와 규칙.
   - 출력(구조화 JSON): 행동 해석, 가능 여부, DC(설정 범위 내, 기본 2~6), AP 비용(기본 1~3), 성공 시 효과 목록, 대실패 시 역효과 목록, 서술 문구.
   - 시스템 프롬프트는 플레이어 입력을 "행동 선언" 데이터로만 다루게 하고, 판타지 전장 해설자 말투의 한국어 서술을 요구한다.
   - GM 출력은 엔진이 스키마와 규칙으로 다시 검증한다. 어긋나면 거부하고, AP를 차감하지 않고, 플레이어에게 안내한다.
   - 확인 단계(해석·DC·비용 제시)에서 LLM 호출 1회가 일어난다. 시도할 때는 이미 받은 결과를 쓰므로 추가 호출 없이 주사위만 굴린다. 서술을 결과에 맞게 다시 생성할지는 구현 중에 정한다.
4. **LLM 제공자 어댑터.** 공통 인터페이스(프롬프트 + 출력 스키마 → 구조화 결과) 뒤에 Claude, OpenAI, Gemini 어댑터를 둔다. 모두 방장 브라우저에서 직접 호출하며, 브라우저 직접 호출에 필요한 각 제공자의 설정은 구현 시 공식 문서로 확인한다. 로컬 모델(Ollama 등)은 나중에 추가한다.
5. **세션/네트워크 모듈.** PeerJS 연결, 방장↔참가자 메시지 프로토콜(참가자 → 방장: 명령 요청, 방장 → 참가자: 상태 스냅샷과 이벤트), 재접속 처리, 방장 이탈 시 일시정지. 핫시트 모드는 같은 인터페이스를 로컬로 구현한다.
6. **저장 모듈.** 방장 브라우저 로컬 저장소에 매 턴 상태 스냅샷을 저장하고 복원한다. API 키는 게임 저장에 넣지 않고, 방장 브라우저에만 따로 기억한다(제공자별, 새로고침해도 유지, 상대에게는 전송하지 않음).
7. **3D 장면.** 체스판, 기물, 주사위를 react-three-fiber로 그린다. 엔진 상태를 받아 표시만 하며, 게임 규칙을 알지 않는다.
   - 기물은 처음에는 코드로 만든 회전체 모양의 클래식 체스 말로 시작하고, 나중에 3D 모델 파일로 바꿀 수 있게 기물 표현을 한 곳에 모은다.
   - 태그 표현: 탑승은 운반 기물 위에 올라탄 모습, 기절은 머리 위에 도는 별, 보호막은 반투명 구체, 자유 태그는 이름표. 화려한 이펙트는 범위 밖.
   - 카메라: 각 플레이어 진영 쪽 비스듬한 시점에서 시작. 회전과 확대 가능. 시점 초기화 버튼과 위에서 내려다보는 시점 전환 버튼 제공.
   - 주사위: **결과는 엔진이 먼저 정하고(방장의 난수), 화면은 그 숫자가 나오도록 연출만 한다.** Rapier 물리로 구르게 한 뒤 원하는 면이 위로 오게 맞춘다. 물리 시뮬레이션 결과를 판정에 쓰지 않으므로 방장과 참가자 화면의 결과가 항상 같다. 연출이 끝난 뒤 결과와 효과를 표시하며, 건너뛰기 버튼을 제공한다.
8. **UI (2D 오버레이).** 3D 장면 위에 겹친 일반 화면. 체크 표시, 채팅 로그(행동, 판정 제시, 주사위, 서술), AP 표시, 턴 표시, 시도/취소 확인 창, 턴 종료 버튼, 판례 목록, 방 만들기/참가 화면(제공자·모델·키 입력, 무료 키 안내).

### 턴 규칙 (정밀 정의)

- 턴이 시작되면 해당 플레이어의 AP가 +1 된다(최대 5). 게임 시작 시 AP는 0이다.
- 턴 중에 특수 행동은 AP가 허용하는 만큼 몇 번이든 시도할 수 있다. 실패해도 턴은 계속된다.
- 일반 수는 턴당 최대 1회이며 두면 턴이 끝난다(연속 이동 능력이 있는 기물은 예외, 아래 "이동 능력"). 일반 수 없이 "턴 종료"로 끝낼 수도 있지만, 그 턴에 특수 행동을 하나 이상 시도했어야 한다(아무것도 하지 않고 넘기기는 불가).
- 특수 행동 흐름: 입력 → GM 제시(해석, DC, 비용) → 시도 또는 취소. 취소는 AP 사용으로 치지 않는다. 시도하면 AP를 차감하고 d6을 굴린다.
  - DC 이상: 성공 효과 적용 (6도 보통 굴림이다. 대성공은 없다)
  - DC 미만: 효과 없음 (AP만 소모)
  - 1: 대실패 역효과 적용
- **실패 후 다시 굴리기.** 일반 실패(DC 미만, 1 제외)이면 판정 창이 다시 열려 같은 판정(DC, 효과)으로 다시 굴리거나 그만둘 수 있다.
  - 다시 굴리는 비용은 방 규칙 "실패 후 다시 굴리기"(없음, AP 1·2·3, 기본 AP 1)이다. 처음 시도에 쓴 AP는 돌아오지 않는다.
  - AP가 남는 한 몇 번이든 다시 굴릴 수 있고, 다시 굴린 결과도 일반 굴림과 같다(1 대실패).
  - 대실패(1), AP 부족, 규칙 "없음"일 때는 다시 굴릴 수 없다. 실패로 체크 자동 종료가 일어나면 턴이 넘어가므로 다시 굴릴 수 없다.
  - 다시 굴릴지 정하는 동안에는 다른 수, 선언, 턴 종료를 할 수 없다(그만두기를 먼저 고른다).
  - 판례는 행동 하나에 하나: 다시 굴린 결과가 실패한 기록을 대신하고 다시 굴린 횟수를 함께 남긴다.
- **원턴킬 방지.**
  - 이번 턴에 특수 행동을 한 번이라도 시도했으면 이번 턴에는 어떤 방법으로도 킹을 잡을 수 없다.
  - 특수 행동 결과 처리 후(성공, 실패, 대실패 역효과 모두) 상대 킹이 현재 플레이어의 기물에게 공격받고 있으면 "체크!"를 표시하고 턴을 자동으로 종료한다. 남은 AP는 이월된다.
  - 턴 시작 시점에 이미 상대 킹을 공격할 수 있으면, 특수 행동 없이 일반 수로 잡아 승리할 수 있다. 특수 행동을 쓰면 위 자동 종료 규칙이 적용된다.
  - 이전 턴에 만든 효과를 이용해 AP 없이 킹을 잡는 것은 허용된다.
- 킹은 특수 행동의 효과로 제거할 수 없다. 태그 부여는 가능하다.
- 체크 판정은 핵심 태그를 반영한다. 기절한 기물은 체크를 걸지 못하고, 탑승한 기물은 운반 기물의 이동 방식으로 판정한다. 보호막이 있는 킹도 공격받으면 체크로 표시한다.
- 자신의 킹을 공격받게 두는 수도 허용하며 경고만 표시한다.
- 태그 지속 시간은 턴이 넘어갈 때 감소하고 0이 되면 제거된다. 정확한 감소 시점(누구의 턴 기준인지)은 구현 시 정하고 설정 파일에 명시한다.

### 판례

- 특수 행동 판정(시도된 것)을 "행동 요약, DC, 비용, 결과"로 기록한다.
- 이후 GM 호출 때 판례 목록을 함께 넘겨서 비슷한 행동을 비슷하게 판정하게 한다.
- 판례는 게임 단위로만 유지한다.

### 설정 값 (기본값, 조정 가능)

- AP: 시작 0, 턴당 +1, 최대 5
- 특수 행동 비용: 1~3 AP
- DC 범위: 2~6 (d6. 예전 저장의 d20 범위는 불러올 때 이 값으로 바뀐다)
- 특수 행동 입력 최대 길이: 200자
- 실패 후 다시 굴리기: AP 1 (방 규칙으로 없음, 1, 2, 3)

## Testing Decisions

- **좋은 테스트란:** 외부 동작만 검증한다. 테스트는 "상태 + 명령 → 결과 상태/이벤트/거부"만 보고, 엔진 내부 함수 구조에 의존하지 않는다.
- **주요 테스트 경계(seam): 게임 엔진의 리듀서 인터페이스 하나.** 주사위 값과 GM 결과를 명령의 입력으로 넘기므로, LLM이나 네트워크 없이 모든 규칙을 결정적으로 테스트할 수 있다. 대상:
  - 일반 체스 규칙(캐슬링, 앙파상, 프로모션, 자살 수 허용, 킹 잡기 승리)
  - 핵심 태그(기절 이동 불가, 탑승 동반 이동, 보호막 1회 무효화)와 지속 시간 만료
  - AP 증감, 최대치, 이월, 부족 시 시도 불가, 취소 시 미차감
  - 주사위 구간별 결과(1, DC 미만, DC 이상, 20)
  - 원턴킬 방지 전 경우(AP 사용 턴의 킹 잡기 거부, 특수 행동 후 체크 자동 종료, 턴 시작부터 체크인 경우, 태그를 반영한 체크 판정)
  - GM 출력 검증(허용 목록 밖 효과, 킹 제거 효과, 범위 밖 DC/비용 거부)
- **보조 경계: GM 모듈.** LLM 어댑터를 가짜로 바꿔서, 프롬프트 구성(판례 포함, 입력 길이 제한)과 응답 파싱·검증을 테스트한다. 실제 API 호출은 자동 테스트에 포함하지 않는다.
- 3D 장면은 규칙을 갖지 않으므로 자동 테스트 대상이 아니다. 단, 주사위의 "원하는 숫자를 위로 맞추는" 계산은 순수 함수로 분리해서 테스트한다.
- 네트워크(PeerJS)와 UI는 자동 테스트 대상에서 제외하고 수동으로 확인한다. 엔진이 분리되어 있어서 핫시트 모드로 대부분을 확인할 수 있다.
- **기존 사례:** 저장소에 코드가 아직 없어서 참고할 테스트는 없다. 테스트 러너는 Vite와 잘 맞는 Vitest를 쓴다.

## Out of Scope

- 서버 권위 구조, 계정, 매치메이킹, 공개 서비스 출시 (출시를 검토할 때 별도 스펙)
- 운영자 API 키 제공 (BYOK만 지원)
- 상대 플레이어의 리액션/카운터 (턴은 순수하게 번갈아 진행)
- 로컬 LLM(Ollama 등) 지원
- 방장 조작 방지 (P2P 방장 권위 구조의 알려진 한계)
- 리플레이 (관전과 수 제한시간은 구현 중에 범위에 들어왔다. 아래 "구현 중 결정된 사항" 참고)
- 한국어 외 언어 지원
- 외부 3D 기물 모델 (불꽃, 빛 같은 효과 이펙트는 "GM 연출" 장에서 범위에 들어왔다)
- AI 상대(컴퓨터 플레이어)

## GM 연출 (확장)

### Problem Statement

지금 GM은 결과를 규칙 효과(이동, 제거, 태그, 변환, 생성, 편 바꾸기)와 서술 문장으로만 표현한다. "번개가 내리꽂혀 비숍이 재가 되었다"고 서술해도 화면에서는 비숍이 평범하게 옆으로 튕겨 나갈 뿐이다. 기물의 움직임도 정해진 몇 가지(손으로 옮기는 호, 물리 비행, 떨어지기)뿐이라, 서술과 화면이 따로 논다.

### Solution

GM에게 판정과 함께 "연출"을 쓸 수단을 준다. 연출은 보기용이며 게임 규칙에는 영향을 주지 않는다.

- 정해진 원소 12종의 이펙트를 폭발, 줄기, 영역, 꼬리 네 모양으로, 세기, 지속, 반경을 정해 놓는다.
- 태그에 원소 오라를 붙여 태그가 끝날 때까지 기물이 불타거나 빛나게 한다.
- 이동, 생성, 퇴장마다 움직임 방식과 속도를 고르고, 보드를 바꾸지 않는 제자리 연기도 시킨다.
- 효과를 순서대로, 원하는 간격으로 하나씩 보여 준다.
- 퇴장 방식에 따라 잡힌 기물이 그을리거나, 재 더미, 조각 무더기, 영혼으로 옆자리에 남는다.

### User Stories

2. As a 플레이어, I want 성공, 실패, 대실패마다 다른 연출을 보기, so that 결과의 무게가 느껴진다
3. As a 플레이어, I want 혼돈 사건에도 연출이 붙기, so that 혼돈이 글자로만 지나가지 않는다
4. As a 플레이어, I want 불, 빛, 물, 풀, 어둠, 번개, 얼음, 바람, 독, 마력, 흙, 충격 이펙트를 보기, so that 행동의 성격이 한눈에 보인다

### Implementation Decisions

- **보기용 연출 층.** 연출은 엔진의 규칙 효과와 분리된 데이터다. 엔진은 연출을 검증하거나 적용하지 않고, 판정과 혼돈 사건에 실어 나르기만 한다. 예외는 두 가지다. 태그의 오라와 잡힌 기물의 퇴장 방식은 보드에 남는 모습이라 상태에 저장된다.
- **GM 출력.** 판정 요청 한 번에 결과 셋(성공, 실패, 대실패)의 연출을 함께 받는다. 혼돈 사건도 연출을 함께 낸다. 세 제공자의 구조화 출력 스키마(OpenAI strict 포함)에 맞게, 모든 필드는 필수로 두고 "없음"을 나타내는 값을 쓴다.
- **연출 하나(결과 하나)의 구성:**
  - 이펙트 목록(최대 6개, 전체 6초 이내)
  - 화면 흔들림(0~3)
  - 효과별 연출: 효과마다 앞에 둘 대기 시간(0~2초)과, 이동이면 움직임 방식과 속도, 생성이면 등장 방식, 제거나 효과로 잡힌 기물이면 퇴장 방식
  - 제자리 연기 목록(기물 칸, 연기 종류)
- **이펙트:**
  - 원소 12종: 불, 빛, 물, 풀·덩굴, 어둠·연기, 번개, 얼음, 바람·먼지, 독, 마력, 흙·돌 파편, 충격. 색은 원소마다 고정이다.
  - 모양 4종:
    - 폭발: 중심 칸, 반경 0.5~3칸
    - 줄기: 출발 칸에서 도착 칸
    - 영역: 두 칸으로 정한 직사각형 또는 보드 전체
    - 꼬리: 몇 번째 효과로 움직이는 기물을 따라감
  - 세기 1~5, 지속 0.5~5초(꼬리는 움직이는 동안). 방향은 원소가 정한다(물 영역은 비처럼 내리고, 불은 위로 타오름).
  - 시작 시점은 "몇 번째 효과와 함께" 또는 "연출 시작 후 몇 초"로 정한다.
  - 원소마다 합성 효과음을 자동으로 붙인다.
- **오라.** 태그 효과에 원소와 세기(1~3)를 붙일 수 있다. 지속은 태그를 따르고, 태그가 사라지면 함께 꺼진다. 기물에만 붙고 칸에는 붙지 않는다(규칙 효과로 오해받지 않도록). 기절과 보호막의 기존 표현은 그대로 둔다.
- **움직임:**
  - 이동 방식(8): 날아가기(지금의 물리 비행), 뛰어오르기, 미끄러지기, 순간이동, 돌진, 살금살금, 회전하며 날기, 땅속으로. 속도는 느리게, 보통, 빠르게.
  - 등장 방식(3): 떨어지기(지금의 물리 낙하), 솟아오르기, 빛과 함께 나타나기
  - 퇴장 방식(6): 튕겨 나감(지금의 물리), 불탐, 재가 됨, 사라짐, 가라앉음, 산산조각
  - 제자리 연기(5): 제자리 뛰기, 비틀거림, 넘어졌다 일어남, 부르르 떨기, 한 바퀴 돌기. 어느 결과에서든 쓸 수 있고, 끝나면 기물은 제자리에 선다.
  - 변환, 편 바꾸기, 탑승과 하차, 태그는 정해진 기본 동작(빛나며 모양이 바뀜, 색이 소용돌이치며 바뀜, 폴짝 올라탐)에 GM 이펙트를 얹는다.
  - 일반 체스 수와 그로 인한 잡기는 GM이 관여하지 않는다(움직임은 아래 "구현 중 결정된 사항"의 물리 이동을 따른다).
- **잡힌 기물의 옆자리:**
  - 모습: 불탐은 몇 초 타다가 그을린 채로 연기 한 줄기, 재가 됨은 재 더미, 산산조각은 판 위에 흩어진 조각(아래 "부서진 조각", 사용자 요청으로 무더기에서 바꿈), 사라짐은 반투명하게 빛나며 떠 있는 영혼, 가라앉음은 진흙이 묻은 채, 튕겨 나감은 평범하게.
  - 재 더미와 조각 무더기에는 기물의 특징 부분(킹의 십자가, 나이트의 말머리 등)이 남아 알아볼 수 있다.
  - 잡힌 기물 목록에 퇴장 방식을 함께 저장해 새로고침, 이어 하기, 나중에 들어온 사람도 같은 모습을 본다.
- **재생.**
  - 게임 상태는 지금처럼 한 번에 바뀌고, 화면만 효과 순서대로 차례차례 보인다(주사위 연출이 끝난 뒤).
  - 연출 동안 GM 서술을 자막으로 띄우고 로그에도 남긴다.
  - 건너뛰기 버튼은 내 화면에서만 바로 최종 상태를 보여 준다.
  - 각 화면이 같은 연출 데이터를 받아 따로 재생한다.
- **수 제한시간.** 특수 행동을 시도하면 주사위 5초에 그 결과의 연출 길이(최대 6초)를 더해 준다. 혼돈 연출 시간도 더한다.
- **검증.** 연출은 보기용이라, 잘못된 항목(없는 칸, 없는 원소, 범위 초과, 없는 효과 번호)은 조용히 빼고 판정은 살린다. 규칙 효과가 잘못된 경우에만 지금처럼 판정을 거부한다.
- **기본 연출.** GM이 어떤 결과에 연출을 하나도 주지 않으면 효과 종류에 맞는 수수한 기본 연출을 쓴다. 생성은 마력 반짝임, 제거는 먼지, 기절은 번개 섬광, 편 바꾸기는 어둠 연기 등이다.
- **GM 지침은 가볍게.** 프롬프트에는 쓸 수 있는 도구와 "서술과 맞게, 결과의 크기에 맞게(성공은 화려하게, 실패는 짧게, 대실패는 행동한 쪽에 역효과처럼)"만 적는다. 원소별 공식은 정하지 않는다.
- **가짜 GM.** 자기가 이해하는 행동마다 정해진 간단한 연출을 쓴다(날리기는 바람 꼬리, 저격은 번개 줄기와 산산조각, 소환은 빛 기둥과 솟아오르기 등). 혼돈은 여전히 일으키지 않는다.
- **성능.**
  - 설정의 "연출: 풍부하게 / 가볍게"로 입자 수를 줄이고 화면 흔들림을 끈다. 기본값은 좁은 화면이면 가볍게, 아니면 풍부하게다.
  - 기기의 '동작 줄이기'가 켜져 있으면 흔들림을 항상 끈다.
  - 입자 수에는 상한을 둔다.
  - 배터리(사용자 요청): 3D 화면은 무언가 바뀔 때만 다시 그린다. 애니메이션과 물리는 늘 화면 주사율대로 계산하고, 비싼 그리기만 건너뛴다. 매 프레임 모든 물체의 자리·방향·크기와 카메라를 지난 프레임과 비교해 무언가 움직였으면(공중부양 흔들림이나 오라 같은 끝없는 작은 움직임도) 그 프레임을 그리고, 화면을 만지는 동안도 그린다. 자리가 바뀌지 않는 변화(빛, 입자)는 그 연출이 스스로 알린다. 아무것도 안 바뀌면 초당 2번만 그린다(아무도 알리지 않는 변화, 예를 들어 늦게 불러온 그림을 위해). 처음에는 캔버스 전체를 필요할 때만 돌려서 멈춰 있는 동안 애니메이션 계산도 쉬게 하고 작은 반복 움직임은 초당 30번으로 그렸는데, 휴대폰에서 움직임이 끊겨 보이고 새 움직임이 늦게 시작할 수 있어서 바꿨다. 휴대폰(터치 화면)은 화소 밀도를 1.5배까지만 쓴다.

### Testing Decisions

- 연출 검증(잘못된 항목을 빼고 나머지는 살림, 상한 적용)과 GM 응답 파싱은 순수 함수로 테스트한다.
- 엔진에서는 퇴장 방식이 잡힌 기물 목록에, 오라가 태그에 저장되고 저장과 복원에서 유지되는지를 테스트한다.
- 재생 타임라인(효과별 대기, 이펙트 시작 시점, 전체 길이 계산, 건너뛰기)은 3D와 분리된 순수 계산으로 만들어 테스트한다. 수 제한시간에 더해 주는 시간도 여기서 나온다.
- 파티클과 움직임의 모습은 자동 테스트하지 않고, 스크린샷과 느린 재생으로 확인한다.
  - 개발 서버의 `?fxlab` 페이지에서 게임 없이 이펙트(`fx=`), 이동(`trip=`), 등장(`enter=`), 연기(`act=`), 변환(`morph=`), 편 바꾸기(`swirl=`)를 재생해 볼 수 있다. 배포 빌드에는 들어가지 않는다.
- 세 제공자의 확장된 스키마는 기존처럼 가짜 HTTP로 요청 형식을 확인하고, 실제 키(Gemini)로 수동 점검한다.

### Out of Scope

- 칸에 남는 연출(불타는 땅 등)과 규칙에 영향을 주는 연출
- GM이 고르는 색, 카메라 이동이나 확대
- 일반 체스 수의 연출 변경
- 외부 이펙트 에셋(이미지, 사운드 파일). 모두 코드로 만든다.

## 합과 조형물 (확장)

### Problem Statement

GM은 "폰이 영감을 얻어 검술에 눈을 떴다", "구덩이에 다리를 놓는다", "벽에 사다리를 건다" 같은 선언을 받아도 표현할 수단이 없다. 검술은 이후 판정에서 GM이 참고만 하는 서사용 태그에 그치고, 다리나 사다리는 아예 만들 수 없다. 화면에도 아무것도 생기지 않아, 선언과 보드가 따로 논다.

### Solution

- **조형물.** GM이 기본 도형 블록을 조합하거나 미리 만든 모양을 불러 작은 조형물(검, 사다리, 다리 등)을 만든다. 조형물은 언제나 규칙을 가진 무언가의 모습이다. 기물에 붙으면 태그의 모습이고, 칸에 놓이면 지형(벽, 다리, 사다리)의 모습이다.
- **다리와 사다리.** 다리는 구덩이를 건너게 하고, 사다리는 벽을 넘게 하는 새 지형 규칙이다.
- **합.** 검술처럼 합 배율을 가진 태그가 있거나 보호막이 있는 기물이 잡히려 할 때, 양쪽이 d6을 굴려 (주사위 값)×(배율)을 반올림한 점수로 승부를 낸다. 공격 쪽이 지면 공격 기물이 잡힌다. 결과는 두 기물을 줌인해 물리로 맞부딪치는 결투로 보여 준다.

### User Stories

1. As a 플레이어, I want "폰이 검술에 눈을 떴다"가 실제로 폰 손에 검으로 보이고 싸움에서 힘이 되기, so that 선언이 보드와 승부에 남는다
2. As a 플레이어, I want 검술 기물이나 보호막 기물을 잡으려 하면 합이 일어나기, so that 강해진 기물을 쉽게 잡을 수 없다
3. As a 플레이어, I want 합에서 진 공격 기물이 잡히기, so that 강한 기물을 공격하는 데 위험이 따른다
4. As a 플레이어, I want 합의 주사위 두 개와 계산(12×1.5 = 18 대 15)을 보기, so that 결과를 믿을 수 있다
5. As a 플레이어, I want 합을 두 기물이 맞부딪치는 결투로 보고, 팽팽할수록 오래 싸우는 걸 보기, so that 주사위 결과가 이야기로 느껴진다
6. As a 플레이어, I want 진 쪽이 베여 산산조각 나거나 튕겨 쓰러지기, so that 결판이 분명하다
7. As a 플레이어, I want 합이 일어날 칸과 이길 확률을 공격하기 전에 보기, so that 모르고 공격했다가 억울하게 잃지 않는다
8. As a 플레이어, I want 결투 연출을 건너뛰기, so that 급할 때 기다리지 않는다
9. As a 플레이어, I want 구덩이에 다리를 놓아 건너기, so that 지형을 지형으로 맞받아칠 수 있다
10. As a 플레이어, I want 다리가 끊기면 그 위의 기물이 떨어지기, so that 다리 위에 오래 서 있는 게 위험해진다
11. As a 플레이어, I want 벽에 사다리를 걸어 넘어가기, so that 벽이 영원한 장벽이 아니다
12. As a 플레이어, I want GM이 만든 벽이 바리케이드, 동상, 나무처럼 서술에 맞는 모양이기, so that 같은 벽이라도 이야기가 다르다
13. As a 플레이어, I want 검, 창, 방패, 깃발, 왕관 같은 조형물이 기물의 손, 머리, 등에 제대로 붙어 함께 움직이기, so that 보기 좋고 누가 무엇을 가졌는지 안다
14. As a 플레이어, I want 조형물이 연결된 태그나 지형과 함께 사라지기, so that 보이는 것과 규칙이 늘 같다
15. As a 참가자나 관전자, I want 새로고침하거나 나중에 들어와도 같은 조형물을 보기, so that 모두가 같은 테이블을 본다
16. As a 방장, I want 가짜 GM으로 키 없이 검술, 다리, 사다리, 합을 시험해 보기, so that API 비용 없이 확인할 수 있다

### Implementation Decisions

- **합이 일어나는 경우.**
  - 손으로 잡는 경우만: 일반 체스 수의 잡기(앙파상 포함)와 특수 행동의 이동 효과로 상대 칸에 들어가 잡는 경우.
  - 방어 쪽에 합 배율 태그나 보호막이 있을 때만 일어난다. 공격 쪽 배율은 합이 일어났을 때 계산에만 들어간다. 검술 기물이 평범한 기물을 잡는 건 그냥 잡기다.
  - 저격이나 주문 같은 제거 효과와 혼돈 사건에는 합이 없다(보호막은 지금처럼 한 번 막는다).
- **계산.** 공격 쪽과 방어 쪽이 각자 d6을 굴려 (주사위 값)×(배율)을 소수점 첫째 자리에서 반올림한 정수 점수(사용자 요청: 4.5는 5, 2.4는 2)를 비교하고 큰 쪽이 이긴다. 배율은 기물 종류의 기본 배율 × 태그 배율이다(아래). 같으면 다시 굴린다. 주사위는 방장(권한 쪽)이 굴리고, 엔진은 밖에서 받은 주사위 값으로만 계산한다(엔진은 무작위를 쓰지 않음).
- **배율.** GM이 태그를 붙일 때 "합 배율"(×1.2~×2.0)을 함께 정할 수 있다. 한 기물에 배율 태그가 여럿이면 가장 큰 것 하나만 쓴다. 공격과 방어에 같은 배율이 적용된다. 탄 기물이 있으면 둘 중 큰 배율로 싸운다.
- **기본 배율 (사용자 요청).** 기물마다 기물 점수(폰 1, 나이트·비숍 3, 룩 5, 퀸 9)에 따른 기본 배율이 있다: 0.7 + 0.1 × 점수, 즉 폰 ×0.8, 나이트·비숍 ×1.0, 룩 ×1.2, 퀸 ×1.6. 킹은 점수가 없어 ×1.0이다.
  - 합에서 쓰는 배율은 기본 배율 × 태그 배율(태그가 없으면 ×1)이고 소수 둘째 자리로 맞춘다. 검술 ×1.5인 폰은 ×1.2, 퀸은 ×2.4. 탄 기물이 있으면 각자 계산해 큰 쪽.
  - 합이 일어나는 조건은 그대로다(방어 쪽에 배율 태그나 보호막). 기본 배율만으로는 합이 일어나지 않아, 평범한 체스 잡기는 그대로 잡기다. 예: 평범한 룩이 보호막 나이트를 잡으려 하면 ×1.2 대 ×1.0으로 합을 한다.
  - 진 기물이 베여 부서지는(shatter) 연출은 이긴 쪽이 배율 태그(무기)를 가졌을 때만이다. 기본 배율이 높아도 무기가 없으면 쳐서 넘어뜨린다.
  - 기물 정보 카드에 "합 ×배율"(태그가 있으면 "기본 ×… × 태그 ×…")을 보여 준다. GM 프롬프트도 기본 배율을 안다(엔진 표에서 만들어 넣음).
- **결과.**
  - 공격 쪽이 이기면 보통 잡기와 같다.
  - 공격 쪽이 지면 공격 기물이 잡혀 옆자리로 가고, 방어 기물은 제자리에 있으며, 공격한 쪽의 턴이 끝난다(일반 수일 때).
  - 보호막이 있는 방어 쪽이 지면 기물 대신 보호막만 깨지고, 공격 기물은 자기 칸으로 물러난다. 보호막 자체에는 배율이 없다.
  - 탄 기물이 있는 쪽이 지면 진 기물만 잡히고, 탄 기물은 위에서 굴러떨어진다(아래 "탄 기물 떨어지기").
  - 킹도 합을 한다. 합에서 진 킹은 잡히고 게임이 끝난다. 원턴킬 방지(AP를 쓴 턴에는 킹을 잡을 수 없음)는 그대로다.
- **특수 행동 안의 합.** 이동 효과가 합을 일으키면 연출이 그 효과에서 멈추고 합 주사위와 결투를 보여 준 뒤 이어 간다. 공격 기물이 지면 그 행동의 남은 효과는 취소된다.
- **합 주사위.** 주사위 상자에서 d6 두 개를 차례로 굴린다(사용자 요청으로 함께 굴리던 것을 바꿈): 공격 쪽 주사위가 멈추면 그 최종 점수(주사위 × 배율)가 먼저 크게 뜨고, 0.45초 뒤 방어 쪽 주사위를 던진다. 방어 쪽 주사위는 먼저 멈춘 주사위 사이로 떨어진다(먼저 던진 주사위는 그 자리에 그대로 있다). 각 주사위는 그 편 색이다. 둘 다 멈추면 양쪽 최종 점수(반올림한 정수)를 크게, 주사위 눈과 배율(반올림 전 값이 다르면 "= 4.5 반올림")은 그 아래 작게 보여 주고, 이긴 쪽에 금색 테두리와 "승" 표시를 붙이고 진 쪽은 흐리게 한다. 수 제한시간은 합 하나에 8.5초(주사위)와 결투 시간을 더 준다.
- **합 횟수.** 두 점수 차이로 정한다. 차이 4 이상이면 1합, 3이면 2합, 2면 3합, 1이면 4합이다(d6에 맞춤). 동점으로 다시 굴릴 때마다 1합씩 더하고, 최대 6합이다. 주사위 값에서만 정해지므로 모든 화면에서 같다.
- **결투 연출.**
  - 카메라가 두 기물 옆에서 비스듬히 보도록 당겨진다.
  - 두 기물이 합 횟수만큼 물리로 맞부딪치고, 부딪칠 때마다 충격 불꽃이 튄다. 검 같은 조형물도 기물과 함께 휘둘린다.
  - 결판:
    - 배율 태그를 가진 기물에게 진 쪽은 산산조각 난다.
    - 배율 없는 기물에게 진 쪽은 물리로 튕겨 날아가 쓰러진다.
    - 보호막 기물이 지면 보호막 구체만 깨져 흩어지고, 기물은 뒤로 비틀거린다. 공격 기물은 자기 칸으로 물러난다.
  - 끝나면 원래 시점으로 돌아온다. 전체 4~7초이고, 건너뛰기 버튼이 있다.
  - 설정이 "가볍게"면 최대 2합만 보여 주고, 기기의 '동작 줄이기'가 켜져 있으면 카메라를 움직이지 않는다.
  - 결투 시간은 수 제한시간에서 빠진다.
- **미리 알려 주기.** 기물을 골랐을 때 합이 일어날 대상 기물 위에 칼 두 자루와 이길 확률만 띄운다(예: "⚔ 67%", 50% 이상은 초록, 미만은 빨강). 그 칸의 이동 표시는 금색이다.
- **조형물.**
  - 모든 조형물은 규칙을 가진 무언가의 모습이다.
    - 기물에 붙는 조형물은 태그의 모습이다(검은 검술, 방패는 보호막 등). 어떤 태그든(서사용 포함) 조형물을 붙일 수 있다. 태그가 끝나거나 기물이 잡히면 사라진다.
    - 칸에 놓이는 조형물은 지형의 모습이다(GM이 모양을 정한 벽, 다리, 사다리). 지형이 사라지면 함께 사라진다.
  - 부품: 상자, 원기둥, 원뿔, 공, 쐐기, 고리 같은 기본 도형. 부품마다 위치, 크기, 회전, 재질을 정한다. 조형물 하나에 최대 20개.
  - 재질: 나무, 돌, 쇠, 금, 천(색 지정), 밧줄, 유리, 빛남(원소 색).
  - 미리 만든 모양: 검, 창, 방패, 사다리, 다리, 깃발, 왕관, 바리케이드. 이름으로 불러 쓰고 색이나 크기만 바꿀 수 있다. 그 밖의 것은 자유 조합으로 만든다.
  - 기물에 붙는 곳: 오른손, 왼손, 머리, 등, 발밑. 탄 기물에게도 붙고 작게 보인다.
  - 크기: 기물 조형물은 기물 키의 1.5배 안, 칸 조형물은 한 칸 안(다리는 칸 가장자리까지). 범위를 벗어난 부품은 잘라 내거나 뺀다(보기용 검증처럼 판정은 살린다).
  - 상태에 저장되어 저장과 복원, 온라인 전달, 나중에 들어온 사람 모두 같은 모습을 본다. 혼돈도 같은 효과 어휘를 쓴다.
- **다리.** 구덩이 위에 놓는다. 다리가 있는 동안 그 칸은 평범한 칸처럼 지나가고 설 수 있고, 양편 모두 쓸 수 있다. 남은 턴은 GM이 정하고 지형처럼 만든 쪽의 턴 기준으로 센다. 다리가 끝나거나 효과로 끊기면 구덩이로 돌아가고, 그 위에 서 있던 기물은 떨어진다(킹은 떨어지지 않고 옆 빈 칸으로 밀려난다).
- **사다리.** 벽에 건다. 사다리가 있는 동안 그 벽 칸을 지나갈 수는 있지만 멈출 수는 없다. 양편 모두 쓸 수 있고, 지나갈 수 있으니 체크도 벽을 넘어 통한다. 남은 턴과 치우기는 다리와 같다.
- **GM 지침.** 배율 태그는 ×1.2~1.4면 DC 11~14·AP 2, ×1.5~2.0이면 DC 15~20·AP 3, 영구면 DC +3을 기준으로 한다. 보호막은 합 덕분에 강해졌으니 지금보다 DC +2. 조형물은 서술에 맞게, 미리 만든 모양을 먼저 쓰고 없을 때 자유 조합한다.
- **가짜 GM.** 검술, 다리, 사다리 선언을 이해하고 미리 만든 모양을 쓴다. 혼돈은 여전히 일으키지 않는다.

### Testing Decisions

- 합은 순수 계산으로 테스트한다: 일어나는 경우와 안 일어나는 경우(평범한 방어 쪽, 제거 효과, 혼돈), 배율 고르기(가장 큰 것, 탄 기물), 동점 다시 굴림, 승패별 보드 결과(보호막, 킹, 탄 기물), 특수 행동 안에서 진 뒤 남은 효과 취소, 합 횟수.
- 엔진에는 주사위 값을 밖에서 넣어 결과를 정확히 확인한다.
- 미리 알려 주는 승률은 정확한 확률 계산으로 테스트한다.
- 다리와 사다리는 이동·체크·캐슬링 규칙과 끝날 때(떨어짐, 킹 밀려남)를 테스트한다.
- 조형물 검증(부품 수, 크기, 재질, 붙는 곳, 미리 만든 모양 이름)은 순수 함수로 테스트하고, 저장과 복원에서 유지되는지 확인한다.
- 결투와 조형물의 모습은 자동 테스트하지 않고, 개발 서버의 미리보기 페이지와 스크린샷으로 확인한다.
- 실제 키(Gemini)로 검술, 다리, 사다리, 자유 조합 조형물을 수동 점검한다.

## Further Notes

- **서버비 0원 조건:** 서버비는 들지 않지만 GM 판정마다 LLM API 사용료가 나간다. 이 비용은 방장의 키로 청구된다.
- **P2P 연결 한계:** 일부 네트워크(회사, 학교 등)에서는 TURN 서버 없이 연결이 실패할 수 있다. 핫시트 모드가 대안이다.
- **밸런스:** AP 수치, DC/비용 범위는 첫 플레이 테스트 후 조정할 것을 전제로 한다.
- **구현 중 결정된 사항:**
  - 캐슬링은 체크를 무시한다(체크 상태에서, 공격받는 칸을 지나, 공격받는 칸으로 모두 가능). 자살 수를 허용하는 규칙과 일관되게 하기 위함. (#2)
  - GM은 한 번의 호출에서 성공 서술과 실패 서술을 모두 돌려준다. 주사위 후 추가 호출은 없다. (#4)
  - 게임 시작 시 AP는 둘 다 0이고 백의 첫 턴이 시작되므로 백은 1 AP로 시작한다. (#4)
  - GM 효과는 칸 이름(예: "e4")으로 대상을 가리키고, 목록 순서대로 적용된다. 이동 효과로 상대 기물(킹 제외)이 있는 칸에 가면 그 기물을 잡는다. (#4)
  - Claude GM 기본 모델은 Claude Opus 5.5이고, GM 설정에서 Sonnet 5.5나 Haiku 5.5로 바꿀 수 있다. 판정 깊이(effort)는 플레이어가 기다리는 시간을 줄이려고 기본 "low"로 둔다. (#5)
  - Claude GM은 구조화 출력(JSON 스키마)으로 판정을 받고, 모델이 정책상 거절하면 서버 측 기본 대체 모델(fallbacks: "default")로 다시 시도한다. 보드 상태는 기물 목록과 텍스트 보드 두 가지로 넘긴다. (#5)
  - OpenAI는 Chat Completions의 strict JSON 스키마 출력, Gemini는 generateContent의 `responseJsonSchema`를 쓴다. 세 제공자가 같은 프롬프트와 같은 판정 형식을 쓰고, 응답은 모두 같은 zod 스키마로 다시 검증한다. OpenAI와 Gemini의 모델 이름은 추천 목록만 제공하고 직접 입력할 수 있다(모델 이름이 자주 바뀌기 때문). (#6)
  - 태그 지속 시간은 그 기물 주인의 턴이 끝날 때마다 1씩 줄고, 태그가 붙은 바로 그 턴에는 줄지 않는다. 그래서 적 기물에 건 1턴 기절은 적의 다음 한 턴 동안 정확히 유지된다. GM이 주는 지속 턴 0은 영구를 뜻한다. (#7)
  - 탑승은 tag 효과가 아니라 전용 효과(board/unboard)로 표현한다. 탄 기물은 보드에서 빠져 태운 기물 안에 들어가며, 함께 움직이고, 혼자 움직이거나 공격하지 못한다. 같은 편끼리만, 킹은 탈 수 없다. 탈 수 있는 수에는 제한이 없어(사용자 요청) 이미 누가 타 있으면 그 위에 쌓인다(탄 기물을 태운 기물째 태울 수도 있다). 내릴 때는 맨 위의 기물이 빈 칸으로만 내린다. (#7)
  - 태운 기물이 잡히거나 제거되면 탄 기물도 함께 잡힌다. (#7) → 사용자 요청으로 바뀜: 탄 기물은 굴러떨어지고 물리로 착지한다(아래 "탄 기물 떨어지기").
  - 보호막은 일반 수, 이동 효과, 제거 효과 어느 쪽의 잡힘도 한 번 막는다. 보호막이 깨지면 공격한 기물은 제자리에 남고, 일반 수였다면 그 턴은 끝난다. (#7)
  - 기절한 기물은 일반 수와 이동/탑승 효과로 움직일 수 없고, 공격(체크)도 하지 못한다. 기절한 킹이나 룩은 캐슬링할 수 없다. (#7)
  - 변환과 생성은 킹을 대상으로 하거나 킹을 만들 수 없다. 생성된 기물의 ID는 결정적으로(spawn-1, spawn-2, …) 매겨진다. (#7)
  - 1은 DC와 상관없이 대실패이고 역효과가 적용된다. 대성공은 없다(사용자 요청, 아래 "대성공 없음"). DC가 최대 6이라 6은 언제나 성공이지만 보통 성공이다. 성공 확률 표시는 이 규칙을 반영한다(최소 17%, 최대 83%). (#9)
  - 판례는 시도된 특수 행동마다 기록되고(취소는 제외), GM에게는 최근 20개만 사용자 메시지로 넘긴다(시스템 프롬프트는 캐시를 위해 고정). (#9)
  - 온라인에서는 방장이 백, 참가자가 흑이다. 상태를 바꾸는 코드는 `Authority` 하나뿐이고(핫시트와 방장이 공유), 참가자는 요청(수, 턴 종료, 선언, 시도, 취소)만 보낸다. 주사위 값이나 GM 판정은 참가자가 보낼 수 없다. (#10)
  - 참가자 메시지는 방장 쪽에서 형식을 검증한 뒤에만 처리하고, 차례가 아닌 쪽의 요청은 거부한다. 방장에게서 참가자로 가는 메시지에는 게임 상태, 이벤트, 안내 문구, GM 표시 이름만 들어간다(API 키 없음). (#10)
  - 한 방에는 참가자 한 명만 들어올 수 있고, 나간 참가자는 같은 방 코드로 다시 들어올 수 있다(그동안 게임 상태는 방장에게 유지). (#10)
  - 연결 끊김은 탭을 닫을 때의 작별 신호와 WebRTC 자체의 실패 감지(약 30초)로 알아낸다. 앱 수준 핑은 3분 침묵 후에만 끊는 안전장치다. 백그라운드 탭에서는 브라우저가 타이머를 분 단위로 늦추기 때문에 짧은 시간 제한을 두면 탭만 바꾼 플레이어가 쫓겨난다. (#10)
  - 게임 상태는 바뀔 때마다 게임을 진행하는 쪽(핫시트 또는 방장) 브라우저에 자동 저장된다. 저장 칸은 하나이고, 로비에서 "이어 하기"나 "지우기"를 고른다. 게임 저장에는 GM 종류와 모델만 넣는다. API 키는 이 브라우저에 제공자별로 따로 기억해서 새로고침이나 이어 하기에도 다시 묻지 않는다(사용자 요청으로 '키 초기화'를 없앰). 칸을 비우고 다른 GM으로 저장하면 그 키는 잊는다. 기억된 키가 없는 GM으로 이어 하면 GM 설정 창이 자동으로 열린다. (#11)
  - 방장이 이어 하면 같은 방 코드를 다시 쓰려고 최대 약 30초 재시도한다(새로고침 직후에는 중계 서버가 이전 등록을 잠시 붙잡고 있음). 끝내 안 되면 새 코드로 열고 새 링크를 보내라고 안내한다. (#11)
  - 참가자는 방장과 연결이 끊기면 "게임 일시정지" 화면을 띄우고 같은 방에 자동으로 다시 연결을 시도한다(2초부터 최대 10초 간격). 브라우저마다 고유 ID를 보내서, 같은 참가자가 새 연결로 돌아오면 이전 연결을 대신하고 다른 사람은 거절한다. (#11)
  - 3D 주사위는 Rapier로 실제 물리 시뮬레이션을 먼저 돌려 궤적을 기록한 뒤 재생한다. 엔진이 정한 숫자가 위로 오도록, 충돌 모양은 그대로 두고 눈이 그려진 겉면만 정육면체의 대칭 회전(24가지) 중 하나로 돌려 씌운다. 그래서 움직임과 멈춘 자세는 물리 그대로이고 눈만 엔진 결과와 같다. 각 브라우저가 따로 굴리므로 굴러가는 모습은 다를 수 있지만 나오는 숫자는 항상 같다. (#12)
  - 체스판은 큰 나무 테이블 위에 있고, 주사위 상자는 테이블 위 체스판 왼쪽(보는 사람 기준, 핫시트는 백 기준)에 있다. 주사위를 굴리면 카메라가 상자 쪽으로 갔다가, 결과가 반영되면 원래 시점으로 돌아온다. 주사위는 항상 3D로 굴린다(켜고 끄는 버튼 없음). 상단에 결과와 건너뛰기/확인 버튼이 뜬다.
  - 주사위가 굴러가는 동안 보드는 판정 전 상태를 보여 주고, 결과와 효과는 주사위가 멈춘 뒤에 반영된다. 그동안 들어온 다른 변경은 순서대로 기다린다. 물리 엔진은 큰 파일이라 게임 화면이 열린 뒤 미리 받아 둔다. (#12)
  - 플레이어끼리 채팅할 수 있다. 오른쪽 패널의 "채팅" 탭에서 쓰고, 안 읽은 메시지 수가 표시된다. 채팅은 게임 행동이 아니라 GM에게 가지 않고 저장되지도 않는다. 한 줄, 300자까지. 핫시트에서는 지금 차례인 쪽 이름으로 남는다.
  - AP는 숫자로 표시하지 않고 테이블 위 금화로 보여 준다. 보는 사람 기준 체스판 오른쪽에 플레이어마다 나무 접시가 있고(자기 쪽에 가까운 것이 자기 것), AP가 늘면 테이블 오른쪽 끝의 가상의 딜러가 물리 엔진으로 금화를 던져 접시에 떨어뜨린다. AP를 쓰면 위에 있는 금화부터 딜러 쪽으로 날아가 사라진다. 접시와 체스판 사이 테이블에 칼로 그은 탤리 마크(다섯 개마다 대각선)로 보유량을 기록하고, 새 마크는 칼이 긋는 연출과 함께 생기며 줄어든 마크는 흐려져 사라진다. 판정 창에도 보유량은 표시하지 않고 비용만 보여 준다.
  - 화면 위쪽에는 차례, 내 색, 체크와 판정 중 같은 상태 표시와 자주 쓰는 버튼(시점 초기화, 위에서 보기, 📜 판례, ⚙ 설정)을 둔다. 설정 메뉴에는 GM 설정, 전체화면(브라우저가 지원할 때만), 효과음, 나가기를 묶었다. 오른쪽 아래 기록·채팅 패널은 접어서 입력 줄만 남길 수 있다.
  - 기물은 움직일 때 들렸다가 호를 그리며 이동해 내려앉는다(나이트는 더 높이 뛰고, 특수 행동으로 멀리 가면 크게 날아간다). 잡히거나 제거된 기물은 공격한 기물이 내려앉을 때 튕겨 나가 체스판 옆(주사위 쪽, 그 기물을 잡은 쪽 가까이)에 작게 줄을 선다. 잡힌 기물 목록은 게임 상태에 기록되어 저장·온라인 동기화된다.
  - 효과음은 오디오 파일 없이 브라우저에서 합성한다: 버튼 클릭, 턴 넘김, 체크, 기물 내려놓기, 잡힌 기물이 튕겨 나가고 떨어지는 소리, 주사위가 부딪히는 소리(물리 시뮬레이션의 충돌 순간에 맞춤), 대실패, 금화가 날아오는 소리와 부딪히는 소리(역시 충돌 순간에 맞춤), 금화를 거둬 가는 소리, 칼로 긋는 소리, GM 판정 도착, 채팅 수신. 설정 메뉴에서 끄거나 음량을 조절할 수 있고 브라우저마다 기억한다.
  - "턴 종료"는 그 턴에 특수 행동을 하나 이상 시도했을 때만 된다(실패해도 시도로 친다, 취소는 치지 않는다). 아무것도 하지 않은 채 턴을 넘길 수는 없고, 버튼도 비활성화된다. 예외로 움직일 수 있는 기물이 하나도 없으면(모두 기절했거나 막혔을 때) 바로 턴을 넘길 수 있다.
  - 첫 화면(로비) 맨 위에 "VERY TACTICAL CHESS" 제목을 크게 두고, 배경에는 게임과 같은 테이블 장면을 카메라가 돌며 보여 준다: 체스판을 한 바퀴 돌고, 주사위 상자로 가서 d6을 실제로 굴리고, 금화 접시로 가서 딜러가 금화를 던져 쌓는다. 접시가 다 차면(5개) 카메라가 체스판을 보는 동안 딜러가 거둬 간다. 주사위와 금화는 매번 새로 물리 계산을 한다.
  - 메뉴가 화면보다 길면 언제나 스크롤로 끝까지 닿는다(가운데·아래 정렬에서 넘친 위쪽이 잘리지 않게). 높이 600px 미만의 가로 화면(가로로 든 휴대폰)에서는 메뉴를 왼쪽에, 제목을 오른쪽 위에 작게 두고, 한 줄 소개를 숨기며, 시작 버튼들을 두 칸씩 놓아 메뉴가 한 화면에 들어온다(사용자 요청: 가로 화면에서 메뉴가 세로로 잘림).
  - 첫 화면에도 "⚙ 설정"이 있다: GM 설정(방을 만들거나 핫시트로 시작할 때 쓸 GM), 전체화면, 효과음. 온라인 대전 안내는 접힌 한 줄로 둔다.
  - 금화는 무겁게 느껴지도록 중력을 세게(장면 기준 9.81×4) 하고 던지는 속도는 √비율로 키워 궤적 모양은 그대로 둔 채 더 빨리 떨어지게 했다. 접시에 내려앉으면 강한 감쇠로 바로 멈추고(흔들거리며 오래 굴지 않음), 한 번의 던지기는 최대 4.5초다. 부딪히는 소리에는 낮은 "쿵"을 더했다.
  - 폰은 그 편의 마지막 줄에 생성(spawn)하거나 그 줄에서 폰으로 변환할 수 없다(움직일 수 없는 폰이 생기지 않게). 이동·하차 효과로 폰이 마지막 줄에 도착하면 일반 수처럼 승격하는데, 고를 수 없으니 항상 퀸이 된다. 그 밖의 길로 폰이 마지막 줄 땅 칸에 서게 되어도(탄 기물이 굴러떨어지거나 공중부양이 끝나 내려앉아서) 명령이 끝날 때 퀸으로 승격하고, 그 퀸이 체크를 걸면 체크도 알린다(사용자 제보로 고침: 낙하로 내려앉은 폰이 승격하지 않았음). 가짜 GM도 생성("e4에 나이트를 소환한다")과 변환("a2 폰을 퀸으로 바꾼다")을 이해한다.
  - 방에 들어오면 바로 시작하지 않고 대기실을 거친다. 방장을 포함해 들어온 사람은 모두 대기석에 앉고(방 전체 최대 10명), 판의 자리(백, 흑, 육각 판이면 적) 가운데 빈 자리를 스스로 골라 앉는다. 앉은 사람은 일어나 대기석으로 돌아가거나 다른 빈 자리로 바로 옮길 수 있고, 이미 누가 앉은 자리에는 앉을 수 없다. 방장은 앉은 손님을 대기석으로 돌려보낼 수만 있다(대신 앉혀 주지는 않는다). 판을 2인으로 바꾸면 적 자리에 앉은 사람은 대기석으로 간다. 모든 자리에 연결된 사람이 있어야 시작할 수 있고, 게임 중에는 자리를 바꿀 수 없으며 대기석에 남은 사람은 관전자가 된다. 게임이 끝나면 모두 대기실로 돌아간다. 핫시트도 규칙을 정하려고 대기실을 거치고, 저장된 게임을 이어 할 때만 대기실을 건너뛴다.
  - 대기실에는 참가자 목록(역할, 이름, 연결 상태), 규칙, 채팅, 초대 코드가 있다. 이름은 대기실에서 바꾸고 브라우저에 기억된다. 다른 사람에게는 공개용 멤버 키만 보내고, 재접속에 쓰는 브라우저 ID는 방장 쪽에만 둔다(남의 자리를 가로챌 수 없게). 게임 중 끊긴 플레이어는 자리를 지키고, 관전자는 나가면 목록에서 빠진다. 방장 쪽 저장에는 누가 어느 자리에 앉았는지(방장 자리와 손님들의 자리)가 함께 저장되어, 이어 하기 후 방장은 자기 자리에서 시작하고 손님은 돌아오면 다시 제자리에 앉는다(자리 고르기 전의 저장은 방장 백, 손님 흑으로 읽는다).
  - 관전자는 모든 것을 보고 채팅과 낙서를 할 수 있지만 수와 특수 행동은 못 한다. 채팅은 방 안의 모두에게 가며 이름으로 표시된다.
  - 방 규칙(방장이 대기실에서 정함): 수 제한시간(없음/30초/1분/90초/2분/3분, 기본 없음), 시간 초과 벌칙(AP 1~3 차감, 기본 1), 턴마다 받는 AP(1~3, 기본 1), 혼돈(끔/10%/25%/50%, 기본 끔), 낙서 모드(기본 켬). 규칙은 게임 상태에 들어 있어 저장되고, 게임 중에는 ⚙ 설정에서 볼 수 있다.
  - 수 제한시간은 내 차례에만 흐르고, GM이 판정하거나 혼돈을 만드는 동안에는 멈춘다. 특수 행동을 시도하면 주사위 연출 시간으로 5초를 더 준다. 시간이 다 되면 벌칙만큼 AP를 잃고(가진 만큼만), 대기 중인 판정은 취소되며, 턴이 넘어간다. 시계는 방장 쪽에서만 돌고 다른 사람에게는 남은 시간을 보내 각자 화면에서 줄어든다. 마지막 5초에는 똑딱 소리가 난다.
  - 혼돈: 라운드마다(양쪽이 한 번씩 두고 백의 차례가 시작될 때) 정한 확률로 방장의 GM(API)이 기상천외한 사건(제목, 해설, 효과 1~3개)을 지어낸다. 일어날지 말지는 방장 브라우저가 확률로 정하고(매번 API를 부르지 않도록). 처음에는 차례가 넘어갈 때마다 굴려서 매 수 뒤에 혼돈이 붙어 나오는 것처럼 보였기에 라운드마다 한 번으로 바꿨다, 무슨 일이 일어날지는 전부 API가 정한다. API에는 몇 가지 예시를 "분위기를 보여 주는 참고일 뿐이니 따라 하지 말고 보드 상황에 맞게 새로 지어내라"는 지시와 함께 보낸다. 가짜 GM이나 API 키가 없는 GM으로는 혼돈이 일어나지 않고, 대기실과 게임 첫 안내에서 방장에게 그렇게 알린다. 효과는 특수 행동과 같은 어휘에 "편 바꾸기(convert)"가 더해졌다("백의 폰은 사실 흑의 스파이였습니다!"). AP와 주사위 없이 적용되고, 킹은 건드릴 수 없으며, 사건 뒤에 어느 쪽 킹이든 공격받게 되면 사건 전체가 취소된다(공짜로 킹을 잡는 일이 없게). GM 오류나 규칙 위반이면 "혼돈이 일어나려다 잠잠해졌습니다"라고만 알리고 넘어간다. 일어난 혼돈은 기록되어 이후 판정과 혼돈 때 GM에게 전달된다. 화면에는 큰 배너와 효과음으로 알린다.
  - 혼돈의 배경은 두 중세 왕국이 맞붙은 전장이다(킹은 왕, 퀸은 왕비, 비숍은 주교, 나이트는 기사, 룩은 성탑과 공성 병기, 폰은 농민병). 지침은 사건을 대부분 그 세계의 일(날씨와 재해, 역병, 반란, 칙령, 교회, 기사도, 공성전, 용병과 첩자, 가끔 중세 전설의 마법)로, 기물의 정체와 엮어 짓게 하고, 총·기계·근대의 것은 쓰지 않게 한다. 예시도 중세 사건으로 바꾸고, 보드를 바꾸는 사건을 앞에 두었다. 실제 Gemini(gemini-3.5-flash-lite) 점검 15건: 모두 중세 사건(마법사의 탑, 음유시인, 대관식, 봉화, 농민 반란, 홍수, 결투 재판, 용병 합류, 투석기, 첩자)이고 모두 규칙에 맞았다. 예시를 바꾼 뒤 7건 중 5건이 보드를 바꿨다(전에는 8건 중 4건이 태그만).
  - 혼돈을 요청할 때마다 방장 쪽에서 무작위 "영감" 단어 두 개(중세 낱말: 예를 들어 공성전, 순례자)를 함께 보낸다. GM은 출발점으로 삼거나 무시할 수 있다. 영감 없이 시험했을 때 같은 사건("전장의 안개")만 반복되어 넣었다. 프롬프트는 태그만 붙이는 사건보다 기물의 위치, 편, 종류가 실제로 바뀌는 사건을 우선하라고 한다.
  - GM이 낸 혼돈이 규칙에 걸리면(예: 사건 뒤 킹이 공격받음) 거부 이유를 붙여 한 번 더 묻고, 그래도 안 되면 넘어간다.
  - GM 서버가 바쁘거나 잠깐 고장(HTTP 500, 502, 503, 504, 529)이면 1.5초 뒤 한 번 다시 보낸다. 그래도 안 되면 "이 모델에 지금 요청이 몰려 있습니다. 다른 모델을 골라 보세요"라고 안내한다.
  - Gemini 기본 모델은 gemini-3.5-flash-lite다. 실제 키로 시험했을 때 gemini-3.8-flash는 수요 과다로 503, 502를 자주 냈고, Flash-Lite는 1~6초 안에 안정적으로 판정과 혼돈을 돌려줬다. 3.8 Flash는 GM 설정에서 고를 수 있다.
  - 편 바꾸기(convert) 효과는 일반 특수 행동에도 쓸 수 있다(매수, 배신 등). 탄 기물도 함께 편을 바꾼다.
  - 낙서 모드(방 규칙, 기본 켬): 게임 화면의 "✏️ 낙서"를 누르면 도구 막대가 열리고, 그동안은 시점이 고정되고 기물을 고를 수 없다. 펜(가늘게/굵게, 6가지 색)으로 보드나 테이블 위에 끌어서 그리고, 메모 도구로 짧은 글(40자)을 원하는 곳에 놓는다(놓은 사람 쪽에서 바로 읽히는 방향). 지우개로 내 낙서를 누르면 지워지고(방장과 핫시트는 누구 것이든), ↶로 내 마지막 낙서를, 아래 버튼으로 내 낙서 전부(방장은 전부)를 지운다. 낙서는 방 안 모두(관전자 포함)가 함께 보고 그리며, 저장되지 않고 새 게임을 시작하면 지워진다. 방 전체 낙서는 최대 300개, 한 획은 최대 400점이다.
  - 기물에도 강체 물리(Rapier)를 쓴다. 잡히거나 제거된 기물은 공격한 기물이 닿을 때 튕겨 나가 테이블 위를 구르며 주사위 쪽 옆자리에 떨어지고, 테이블, 보드 가장자리, 주사위 상자, 먼저 잡힌 기물과 부딪힌다(누운 채로 멈출 수도 있다). 특수 행동이나 혼돈으로 생긴 기물은 칸 위에서 떨어져 내려앉고, 특수 행동이나 혼돈으로 옮겨진 기물은 실제로 날아가 착지한 뒤 그 칸에 똑바로 선다(튕겨 나가면 살짝 뛰어 돌아온다). 일반 체스 수는 물리 이동(아래)을 쓴다. 물리는 주사위·금화처럼 미리 계산해 재생하고, 계산할 수 없으면 기존 연출로 대신한다. 게임 판정에는 영향이 없다.
  - GM 연출(#13~#20): 판정은 결과 넷의 연출을, 혼돈은 사건의 연출을 함께 받는다. 엔진은 연출을 사건 이벤트에 실어 나를 뿐 검사하지 않고, 화면이 그것을 재생한다. 잘못된 항목(없는 원소·모양·칸, 범위 밖 숫자, 없는 효과 번호)은 조용히 빠지고 판정은 그대로 진행된다. 제공자에게는 허용 값(enum)을 담은 엄격한 스키마를 보내고, 응답은 느슨한 스키마로 읽은 뒤 정리한다.
  - 재생: 게임 상태는 한 번에 바뀌고, 화면은 효과마다 그때까지 적용한 보드를 차례로 보여 준다. 주사위 뒤에는 카메라가 돌아오는 0.6초를 기다린 뒤 시작한다. GM 서술은 자막으로 뜨고(넓은 화면은 왼쪽 아래, 좁은 화면은 위), 자막의 건너뛰기는 내 화면에서만 최종 상태로 넘긴다. 연출 중에는 보드를 조작할 수 없고, 그동안 온 다른 변경은 순서대로 기다린다.
  - 연출 시간표는 순수 계산이다: 효과마다 대기 뒤에 움직임 방식과 속도로 정한 시간만큼, 이펙트는 "몇 번째 효과와 함께 + 지연" 또는 시작 기준, 전체가 6초를 넘으면 비율로 줄인다. 수 제한시간에는 주사위 5초에 이 길이를 더하고, 혼돈도 연출 길이만큼 더한다.
  - 파티클은 세 층(빛나는 입자, 연기, 조각)의 고정 크기 풀로 그리고(최대 2600/1100/600개), 원소마다 색과 움직임이 정해져 있다. 번개는 꺾인 줄기 모양으로 몇 번 내리치고, 빛은 기둥, 충격과 물은 바닥을 따라 퍼지는 고리를 더한다. 원소마다 합성 효과음이 붙는다.
  - 움직임: 연출이 있는 판정과 혼돈에서만 GM이 고른 방식을 쓴다. 고르지 않은 이동은 물리 비행, 생성은 물리 낙하다. 변환은 납작해졌다 빛나며 모양이 바뀌고, 편 바꾸기는 보라빛으로 돌며 바뀌고, 탑승은 호를 그리며 올라탄다. 이동 효과로 잡힌 기물은 공격한 기물이 도착할 무렵 퇴장한다.
  - 퇴장 방식은 잡힌 기물 목록에 함께 저장된다(그 기물을 잡은 효과의 연출에서, 탄 기물은 태운 기물을 따라). 튕겨 나감은 저장하지 않는다(평범한 모습). 재 더미와 조각 무더기에는 킹의 십자가, 퀸의 왕관, 나이트의 말머리, 비숍의 모자, 룩의 성벽, 폰의 머리가 남는다. 일반 체스 수로 잡힌 기물은 바뀌지 않는다.
  - 오라는 태그에 저장되고, 태그가 끝나면 함께 꺼진다. 오라 입자는 각 풀의 45%까지만 쓴다(연출이 늘 들어갈 자리가 남도록).
  - GM이 어떤 결과에 연출을 하나도 주지 않으면 기본 연출(생성 마력 반짝임, 제거 먼지, 기절 번개, 보호막 빛, 편 바꾸기 어둠, 오라 태그는 그 원소)을 쓴다. 이동과 탑승, 변환은 기본 동작이 있어 이펙트를 더하지 않는다.
  - 설정의 "연출: 풍부하게 / 가볍게"는 브라우저마다 기억한다. 가볍게는 입자를 40%로 줄이고 흔들림을 끈다. 처음 값은 폭 600px 이하면 가볍게다. 기기의 '동작 줄이기'가 켜져 있으면 흔들림은 항상 없다.
  - 개발 서버의 `?fxlab` 페이지에서 게임 없이 이펙트, 움직임, 퇴장, 오라를 재생해 본다(배포 빌드에는 없음).
  - 실제 Gemini 점검(gemini-3.5-flash-lite, 판정 7건과 혼돈 4건): 모두 형식에 맞았고 연출 항목 80개(이펙트 31, 효과별 연출 23, 연기 26) 중 빠진 것은 없었다. 연출은 서술과 맞았다: 불붙은 나이트의 돌진은 불 꼬리와 돌진과 불탐 퇴장, 퀸의 번개는 d1에서 c6로 번개 줄기와 산산조각, 땅속 비숍은 땅속으로 이동과 흙, 얼음 갑옷은 얼음 오라, 독안개는 독 줄기와 재가 됨. 결과마다 달랐다(대성공은 세기와 흔들림이 크고, 실패는 행동한 기물의 비틀거림이나 떨림, 대실패는 넘어짐). 응답 시간은 판정 2.9~4.2초(평균 3.7초), 혼돈 1.3~2.2초로, 연출이 없던 때(1~6초)와 비슷해 필드 설명이나 상한은 바꾸지 않았다.
- **맞바꾸기, 되살리기, 화상, 지형 (GM 효과 추가)**
  - 맞바꾸기(swap): 두 칸의 기물이 자리를 맞바꾼다. 편은 상관없고 킹도 된다(잡거나 없애는 것이 아니므로). 탄 기물은 태운 기물과 함께 가고, 기절한 기물은 맞바꿀 수 없다. 화면에서는 두 기물이 동시에 떠올라 서로 오른쪽으로 비켜 엇갈리며 날아간다(물리 비행 둘은 공중에서 부딪히므로 정해진 궤적). GM이 움직임 방식을 고르면 그 방식으로 가되 똑같이 비켜 간다.
  - 되살리기(revive): 잡혀서 옆자리에 있는 그 편, 그 종류의 기물 중 가장 최근에 잡힌 것을 빈 칸에 되살린다. 같은 ID로 돌아오고 옆자리 목록에서 빠지며, 태그와 탄 기물은 없이 돌아온다. 같은 효과 목록 앞쪽에서 잡힌 기물도 되살릴 수 있다. 킹은 되살릴 수 없다. 화면에서는 옆자리에서 빛나며 높은 호를 그리고 날아오고, GM이 rise나 materialize를 고르면 옆자리에서 사라졌다가 칸에서 솟아오르거나 빛에서 생겨난다. GM에게는 잡힌 기물이 편과 종류별 개수로 전달된다.
  - 화상: 시스템이 규칙을 강제하는 네 번째 핵심 태그다. 남은 턴은 다른 태그와 같이 그 기물 주인의 턴이 끝날 때만 줄고(붙인 그 턴은 세지 않음), 그 사이에 기물이 칸을 옮기면(일반 수, 캐슬링, 이동·맞바꾸기·탑승·하차 효과 어느 것이든) 불이 꺼진다. 턴이 다할 때까지 옮기지 않으면 그 기물 주인의 턴이 끝나는 순간 타서 없어지고, 옆자리에 재 더미로 남는다. 보호막이 있으면 보호막이 대신 깨지고 불도 꺼진다. 킹에는 붙일 수 없고 영구(0턴)일 수 없다. 탄 기물은 태운 기물이 타면 함께 떨어진다. 타서 없어진 뒤 킹이 공격받게 되면 체크를 알린다. 불을 붙이는 행동에는 서사용 태그 대신 화상을 쓰라고 GM에게 지시하고, GM이 오라를 주지 않아도 화상 기물은 불 오라를 두른다.
  - 지형: 벽(wall)과 구덩이(pit). 어떤 기물도 그 칸에 들어가거나 지나갈 수 없다(룩·비숍·퀸의 길, 폰의 전진, 캐슬링 사이 칸을 막고 체크도 막는다). 나이트는 뛰어넘는다. 효과로 옮기는 기물도 지형 칸에 내려앉을 수 없고, 생성·되살리기·하차도 마찬가지다. 벽은 빈 칸에만 세운다. 구덩이를 기물이 있는 칸에 파면 그 기물이 빠져서 없어지고(킹 불가, 보호막이 있으면 보호막만 깨지고 구덩이는 생기지 않음), 이동 효과로 기물을 구덩이 칸에 보내면 그 기물이 날아가 빠진다(밀어 떨어뜨리기). 빠진 기물은 가라앉음(진흙) 모습으로 옆자리에 남는다. 지형의 남은 턴은 만든 쪽(그 턴의 차례인 편)의 턴이 끝날 때만 줄고, 0은 영구다. 한꺼번에 최대 12칸. clearTerrain 효과로 없앨 수 있다. GM 보드 격자에는 벽 #, 구덩이 O로 보이고 목록으로도 전달된다. 화면에서 벽은 돌을 쌓은 담이 보드에서 솟아오르고, 구덩이는 흙 테두리가 있는 검은 구멍이 열린다. 사라질 때는 가라앉거나 닫힌다.
  - 남은 턴 표시: 시한이 있는 태그(핵심 태그 포함)와 지형 위에 "화상 2", "기절 1", "벽 3" 같은 작은 표시가 뜬다. 카메라 거리와 상관없이 화면에서 같은 크기로, 다른 기물에 가려지지 않게 그린다. 화상의 마지막 턴(1)은 빨갛게 표시한다. 영구 핵심 태그는 숫자 없이 기존 표현(보호막 구체 등)만, 영구 자유 태그는 이름만 띄운다. 기물 정보 카드에는 "화상 (2턴 안에 움직이지 않으면 타 버림)"처럼 쓴다.
  - 가짜 GM은 "b1과 g8의 자리를 바꾼다", "e6 폰이 e7 폰에 불을 붙인다"(화상 3턴), "d1 퀸이 d3에 나이트를 되살린다", "e2 폰이 d4에 벽을 세운다"(2턴, 칸 여럿이면 최대 3개), "e2 폰이 e5에 구덩이를 판다"(2턴), "e3 폰이 d4 벽을 부순다"를 이해한다.
- **주체와 거리 (행동의 당위성)**
  - 모든 특수 행동에는 그것을 하는 선언자 쪽 기물(주체)이 있어야 한다. "폰에 불을 붙인다"처럼 주체가 없는 선언은 불가능 판정이고, GM이 "누가 하는지 정해 주세요. 예: e6의 폰이 e7의 폰에 불을 붙인다"처럼 다시 선언하는 법을 알려 준다. 혼돈은 자연재해나 운명 같은 사건이라 주체가 없다.
  - 판정에는 주체 칸(actor)과 수단(means)이 붙는다. 수단은 근접(touch: 불 붙이기, 밀치기, 붙잡기, 올라타기), 원거리(ranged: 불화살, 던지기, 저격), 마법(magic: 주문), 이동(move: 주체가 직접 달려가거나 날아감) 넷이다.
  - 거리는 킹 걸음 수(가로·세로 칸 차이 중 큰 쪽)로 센다. e6–e7과 e6–d7은 1칸, b1–g8은 7칸.
  - 시스템이 지키는 것: 주체 칸에 선언자 쪽 기물이 있어야 하고, 기절한 기물은 주체가 될 수 없다(다른 기물이 깨우는 건 된다). 근접이면 효과가 작용하는 모든 칸이 주체에서 1칸 이내여야 한다. 거리는 효과를 적용하는 그 순간 주체가 서 있는 칸에서 재므로, 주체가 먼저 다가간 뒤 손을 쓰는 것은 된다. 대실패 역효과는 검사하지 않는다(역효과는 주체가 받는다).
  - GM이 판단하는 것: 원거리와 마법이 그럴듯한지. 원거리는 멀수록(2~3칸 보통, 4~5칸 어려움, 6칸 이상 매우 어려움), 사이가 가로막힐수록(+2~4) DC를 올린다. 사이가 막혀도 불가능은 아니다(포물선으로 쏘는 화살). 마법은 기물에 따라(비숍·퀸은 쉽고, 나이트·룩은 보통, 폰·킹은 어렵게) DC를 정한다. 나이트의 돌진, 룩의 투석기나 궁수처럼 기물 종류에 어울릴수록 쉽다.
  - GM에게 보내는 메시지에는 선언에 나온 칸, 그 칸에 무엇이 있는지, 칸 사이 거리가 미리 계산되어 들어간다.
  - GM 판정이 규칙에 어긋나면(주체 없음, 근접인데 멂, 응답 형식 오류 등) 그 이유를 붙여 GM에게 한 번 다시 묻는다. 두 번째 답이 또 어긋나면 그때 거부를 알린다(AP는 쓰지 않음).
  - 판정 카드에는 "d1 퀸 · 원거리 → d7 6칸"처럼 주체, 수단, 대상과 거리가 나오고, 판정이 기다리는 동안 보드에서 주체 칸은 금색, 대상 칸은 주황으로 강조된다.
  - 이 규칙 전에 저장된 판정(주체 정보가 없는 것)은 검사 없이 그대로 쓴다.
- **합과 조형물 (#21~#25)**
  - 합 주사위는 엔진 밖(방장의 권한 쪽)에서 굴려 명령에 실어 보낸다. 수나 시도가 합을 일으킬 때만 굴리고(엔진이 "합 주사위 필요"로 알려 주면 그때 12개를 굴려 다시 적용), 엔진은 받은 값을 순서대로 쓴다. 동점이 다섯 번 넘게 이어져 주사위가 모자라면 방어 쪽이 버틴 것으로 한다(실제로는 일어나지 않음).
  - 점수는 백분의 일 단위로 비교한다(9×1.5와 13.5가 같게, 부동소수 오차가 승부를 정하지 않게). 미리 알려 주는 승률은 동점을 다시 굴린다는 전제의 정확한 확률이다(×1.5 대 ×1은 267/394 ≈ 68%).
  - 합 배율이 1 이하면 없음, 2.0을 넘거나 1.2보다 작으면 GM 경계에서 범위 안으로 맞춘다(판단이지 오타가 아니므로 거부하지 않음). 엔진은 1.2~2.0만 받는다.
  - 합에서 진 공격 기물은 배율을 가진 기물에게 졌으면 산산조각, 아니면 평범하게 옆자리로 간다. 이긴 공격 기물이 배율을 가졌으면 잡힌 방어 기물도 산산조각.
  - 결투는 Rapier로 미리 계산해 기록한다: 공격 기물이 방어 기물 0.95칸 앞까지 다가가고, 합마다 둘이 마주 달려 부딪친 뒤 제자리에 다시 선다. 마지막 합에서 이긴 쪽이 세게 치고, 결판에 따라 진 쪽이 튕겨 날아가거나(물리), 제자리에 멈춘 뒤 산산조각 나거나, 보호막이 터진다. 물리를 쓸 수 없으면 같은 모양의 정해진 움직임으로 대신한다. 결투 길이는 카메라 0.9초 × 2 + 다가가기 0.6초 + 합당 0.75초 + 결판 1.3초다.
  - 결투 카메라는 두 기물 옆 4.2칸, 높이 2.5에서 둘의 가운데를 본다(그 판의 플레이어 쪽에서).
  - 특수 행동 안의 합은 연출을 그 효과에서 멈추고 합 주사위와 결투를 보여 준 뒤, 그 효과부터 남은 연출을 이어 간다(이미 지난 이펙트는 다시 나오지 않음).
  - 조형물 좌표는 칸 단위, 회전은 도. 기물에서는 붙는 곳이 원점이고 x는 기물의 오른쪽, y는 위, z는 앞(상대 쪽). 칸에서는 가운데 바닥이 원점이고 x는 h열 쪽, z는 8줄 쪽. GM에게는 부품마다 x·y·z·width·height·depth·rotX·rotY·rotZ를 따로 받아(모든 제공자의 구조화 출력이 받을 수 있게) 엔진 형식으로 바꾼다.
  - 기물 조형물은 원점에서 기물 키의 0.9배(전체 크기로는 약 1.5배)까지 닿게 줄이고, 칸 조형물은 0.75~0.85칸까지 닿게 줄인다.
  - 사다리는 그 사다리를 건 쪽의 진영 방향에서 벽에 기대고, 다리는 구덩이 위에 떨어지듯 놓인다. 커스텀 벽 모양이 있으면 돌담 대신 그 모양으로 솟아오른다.
  - 다리가 끝날 때 그 위의 킹은 가장 가까운 빈 칸(지형이 없는)으로 비켜난다. 가까운 칸부터 a열·1줄 순서로 찾는다.
  - 가짜 GM은 "e2 폰이 영감을 얻어 검술에 눈을 뜬다"(검술 ×1.5와 손에 검, DC 15, AP 3), "e3 폰이 d4 구덩이에 다리를 놓는다", "e3 폰이 d4 벽에 사다리를 건다", "e3 폰이 d4 다리를 끊는다"를 이해하고, 보호막에는 방패를 들려 준다.
  - 조형물 부품은 GM에게 효과마다 객체 목록으로 받으면 응답 스키마가 너무 깊어져 Gemini가 요청 자체를 거부했다(HTTP 400). 그래서 부품은 한 줄 문자열("도형 재질 x y z 폭 높이 깊이 [회전 3개] [#색]", ;로 구분)로 받고, 읽을 수 없는 줄은 버린다. 세 제공자 모두 같은 형식이다.
- **공중부양 (공중 판)**
  - 보드 위에 같은 모양의 공중 판이 하나 더 떠 있다. 엔진의 보드는 128칸이고, 0~63은 땅, 64~127은 각 칸 바로 위의 공중이다(칸 이름은 "e4^"). 공중부양 태그가 있는 기물만 공중에 있다. 이전 저장(64칸)은 불러올 때 빈 공중 판을 붙인다. 온라인 프로토콜 버전을 3으로 올렸다.
  - 땅의 기물에 공중부양 태그를 붙이면 바로 위 공중 칸으로 떠오른다(그 칸이 비어 있어야 함). 이미 떠 있는 기물에 붙이면 지속만 바뀐다.
  - 공중의 기물은 공중 판에서 평소의 체스 규칙대로 움직이고(지형은 무시, 앙파상과 캐슬링은 땅에서만), 공중의 적만 잡는다. 합도 공중끼리만 일어난다. 땅의 기물은 공중을 지나 다니고 공중의 기물을 잡을 수 없다. 체크도 같은 판끼리만: 공중의 킹은 공중의 적만, 땅의 킹은 땅의 적만 공격할 수 있다.
  - 효과: move와 swap, board는 같은 판끼리만. spawn, revive, 지형, 다리·사다리는 땅에만. 공중에서는 unboard할 수 없다. 주체와 대상의 거리에서 땅의 칸과 그 위 공중 칸은 1칸이다. 일반 수 입력은 "d4^d5^"이고, 땅에 내 기물이 없고 위에 떠 있으면 "d4d5"도 공중으로 읽는다.
  - 떨어지기: 공중부양이 끝나거나(주인의 턴이 끝날 때 세는 보통의 태그 규칙) untag로 떼면, 기물은 공중에서 빠져 "떨어지는 중"(상태의 falling)이 된다. 그동안은 어떤 명령도 받지 않고, 게임을 진행하는 쪽(핫시트, 방장)이 곧바로 물리(Rapier)로 떨어지는 모습을 계산해 land 명령을 보낸다. 씨앗을 함께 보내 모든 화면이 같은 추락을 재생한다. 물리를 쓸 수 없으면 똑바로 떨어진다.
  - 물리 계산: 공중 높이(2.3)에서 살짝 기울고 흔들리며(씨앗으로 정한 작은 밀림과 회전) 떨어져, 보드와 땅의 기물들(움직일 수 있는 물체)과 부딪히고 멈춘다. 멈춘 기물의 몸 가운데(누우면 바닥 옆) 위치가 착지 지점이다.
  - 착지 규칙(엔진): 기물 바닥을 반지름 0.3칸 원으로 보고 고정 격자로 각 칸에 겹친 비율을 센다. 가장 많이 겹친 곳이 보드 밖이면 산산조각, 아니면 겹친 칸을 많은 순으로 보며 기물도 벽도 없는 첫 칸에 선다. 그 칸이 열린 구덩이면 파묻혀 없어진다. 설 칸이 하나도 없으면 산산조각 난다. 여러 기물이 떨어지면 차례로 정하고, 먼저 내려선 기물도 칸을 차지한다.
  - 킹은 떨어져서 죽지 않는다(킹은 일반 수로만 잡힌다): 죽을 자리면 가장 가까운 빈 칸에 내려선다. 보호막이 있는 기물도 보호막이 대신 깨지고 가장 가까운 빈 칸에 내려선다.
  - 화면: 공중 칸 자체는 그리지 않는다(처음엔 반투명 격자판을 띄웠다가 사용자 요청으로 없앴다). 공중에는 필요한 표시만 뜬다: 고른 공중 기물이 갈 수 있는 칸(이것만 클릭을 받아 아래 보드도 그대로 누를 수 있다), 고른 기물·체크된 킹·판정이 가리키는 기물의 고리. 공중의 기물은 보드 위 2.3 높이에 떠서 계속 조금씩 흔들리며 천천히 돈다. 떠오를 때는 1.4초에 걸쳐 올라가고, 공중의 이동은 미끄러지기 대신 떠서 옮겨 간다. 떨어질 때는 녹화를 재생하고, 끝나기 직전에 결과가 보드에 반영되어 선 자리로 천천히 돌아오거나 그 자리에서 부서지거나 가라앉는다. 공중의 합은 공중 판 높이에 보이지 않는 바닥을 깔고 결투한다.
  - 가짜 GM: "e2 폰이 떠오른다", "d1 퀸이 e2 폰을 공중부양시킨다"(2턴), "d1 퀸이 e4 나이트를 떨어뜨린다". 땅이 비고 위에 떠 있는 칸은 공중 칸으로 읽는다.
  - GM 지침: 공중 판 규칙, "e4^" 표기, 공중부양 가격(내 기물 1~2턴 DC 9~13·AP 1~2, 상대 기물은 떨어져 죽을 수 있어 DC 14~18·AP 2~3). 떠 있는 기물이 있으면 보드 그림에 공중 판을 따로 그린다.
- **태그 접기**: 기물 위 태그 표시가 2개 이상이면 "⋯" 하나로 접는다(가장 급한 태그의 색: 마지막 턴의 화상 > 화상 > 기절 > 보호막). 누르면 세로로 펼쳐지고 다시 누르면 접힌다.
- **물리 이동 (밀치며 가기, 세게 던지기)**
  - 일반 체스 수는 판 전체를 물리로 한 번 계산해 재생한다. 판 위의 모든 기물이 움직일 수 있는 물체이고, 벽은 단단하다.
  - 미끄러지는 수(나이트가 아닌 기물, 캐슬링의 킹과 룩): 목표 칸을 향해 일직선으로 한 번 세게 밀고, 보드와의 마찰(옮기는 기물 1.1, 보드 0.55의 평균)로 멈추게 한다. 미는 힘은 그 마찰로 목표 칸 근처에서 멈출 만큼이다. 짧은 거리는 옆으로 기울거나 비켜 가지 않게 하고(똑바로 선 채 미끄러짐), 3칸(가로·세로 거리) 이상이면 앞으로 기울며 넘어진다. 도착 지점의 기물(잡히는 기물 포함)은 들이받혀 밀리거나 날아간다.
  - 던지는 수(나이트, 그리고 특수 행동·혼돈의 default와 fly 이동): 목표 칸보다 0.45~0.9칸 앞(옆으로 ±0.15칸)을 겨냥해 높은 포물선으로 세게 던진다(위로 7.4 + 거리 × 0.5). 튕기고 구르며 떨어진 곳의 기물을 쓰러뜨린다. 특수 행동에서 잡히는 기물은 계산에서 빼고 지금의 퇴장 연출을 따른다.
  - 모두 멈추면(최대 2.2초, 던지기는 2.6초) 옮긴 기물은 입력한 칸으로, 밀린 기물은 제자리로 0.7~1.2초에 걸쳐 똑바로 서며 천천히 돌아온다. 잡힌 기물은 쓰러진 자리에서 옆자리로 간다. 규칙에는 영향이 없다.
  - 같은 수는 모든 화면에서 같은 겨냥으로 던진다(턴 번호와 칸으로 정한 씨앗). 물리 계산 결과는 기기마다 아주 조금 다를 수 있다.
  - 기기의 '동작 줄이기'가 켜져 있으면 예전처럼 손으로 옮기는 호를 그린다. 물리를 쓸 수 없을 때도 예전 방식이다.
  - 결투도 같은 재생 방식으로 바꿨다: 결과가 보드에 반영된 뒤 녹화가 끝나고, 각 기물은 결투가 끝난 자세에서 규칙상의 자리로 천천히 돌아온다.
  - 실제 Gemini 점검(gemini-3.5-flash-lite, 12건): 모두 형식에 맞고 엔진이 받아들였다. 검술(×1.3~1.4, 손에 검), 창술(×1.3, 창), 대가의 검술(×2.0), 마법 방패(보호막에 왼손 방패), 다리, 사다리, 황금 왕관(머리), 파란 깃발(천 색 #3b82f6), 꽃 화관과 해바라기 모자(직접 조합 2~3부품)를 썼다. 처음에는 영구 검술을 DC 12·AP 2로 싸게 매겨서 난이도 기준에 "영구 검술 ×1.5 → DC 18, AP 3" 같은 예를 넣었고, 이후 영구 ×1.3은 DC 15, 영구 ×2.0은 DC 18·AP 3으로 매겼다. 머리 조형물을 머리 위로 띄워 만든 경우가 있어 "head면 머리 꼭대기가 원점"을 지침에 적었다. 응답 시간은 3.7~9.8초(대부분 4~5초)로, 스키마가 커진 만큼 전보다 1초쯤 늘었다.
  - 수단은 플레이어가 선언에 쓴 방법 그대로다. 선언에 없는 화살이나 주문을 GM이 덧붙여 거리를 풀어 주지 않는다. "달려가서 찌른다"처럼 다가가는 말이 있으면 주체가 먼저 대상 옆으로 이동하는 효과를 넣는다. 처음 시험에서 Gemini가 5칸 떨어진 "불을 붙인다"를 "화염 마법"으로 바꿔 통과시켜서 이 지시를 넣었다.
  - 실제 Gemini 점검(gemini-3.5-flash-lite, 지시를 고친 뒤 8건): 주체가 없는 선언과 상대 기물이 주체인 선언은 다시 선언하는 법과 함께 불가능 판정. 인접한 불 붙이기와 붙잡기는 근접, 5칸 떨어진 불 붙이기는 불가능, 불화살과 룩의 궁수는 원거리(DC 12~14), 비숍의 주문 벽은 마법. "b1 나이트가 d7 폰에게 달려가 창으로 찌른다"는 d6로 이동한 뒤 d7 제거. 응답 2~4.5초.
- **이동 능력 (다른 기물처럼, 연속 이동)**
  - 태그에 이동 능력을 함께 줄 수 있다. GM의 tag 효과에 moveAs(기물 종류 목록)와 moveTimes(2~3)를 둔다. 태그가 사라지면 능력도 사라진다. "폰이 룩처럼 이동한다", "폰이 연속으로 두 번 이동할 수 있다" 같은 지속되는 선언을 서사용 태그가 아니라 실제 규칙으로 만들기 위해서다.
  - moveAs: 원래 움직임 대신 그 기물들처럼 움직인다(사용자 요청: 처음에는 원래 움직임에 더했는데, 씌운 움직임과 겹치는 게 문제였다). 잡기와 체크에도 그대로 쓰인다. 원래 움직임도 남기려면 그 종류를 목록에 함께 넣는다("나이트가 비숍처럼도" → [나이트, 비숍]). 이동 태그가 둘 이상이면 가장 나중에 붙은(다시 붙이면 새로 붙은 것으로 침) 태그만 효력이 있다. 대체되는 동안 폰은 앞으로 걷기·두 칸 전진·대각선 잡기·앙파상을, 킹은 캐슬링을 못 한다(목록에 폰이나 킹이 있으면 그 움직임은 쓴다). 폰처럼 움직일 수 있는 기물은 앙파상도 할 수 있다. 앙파상 기회는 폰이 첫 줄에서 두 칸 전진했을 때만 생긴다(룩처럼 두 칸 미끄러진 폰은 아님). 프로모션은 원래 폰인 기물만 한다. 나이트처럼 뛰는 수(ㄱ자)는 어떤 기물이 하든 뛰어넘는 연출로 보인다.
  - moveTimes: 그 기물로 일반 수를 한 턴에 그만큼 연속으로 둔다. 여러 태그가 있으면 가장 큰 값을 쓴다.
    - 첫 수 뒤에는 턴이 넘어가지 않는다. 상태에 연속 이동(chain: 기물, 칸, 남은 횟수)이 남고, 그 기물을 한 번 더 움직이거나 "턴 종료"로 그만둘 수 있다. 그동안 다른 기물은 움직일 수 없고, 특수 행동도 선언할 수 없다.
    - 수를 둔 뒤 상대 킹이 공격받으면(체크) 남은 횟수와 상관없이 턴이 넘어간다. 그래서 한 턴에 체크를 걸고 킹까지 잡을 수는 없다(원턴킬 방지와 같은 취지). 더 갈 곳이 없어도 턴이 넘어간다.
    - 합에서 지거나 보호막에 막히면 보통 때처럼 턴이 넘어간다.
    - 중간에 그만두면 마지막 수로 생긴 앙파상 기회는 상대에게 그대로 남는다.
  - 화면: 연속 이동 중에는 위에 "👣 연속 이동 N번 남음"이 뜨고, 첫 수의 연출이 끝나면 그 기물이 저절로 집혀 갈 수 있는 칸이 보인다. 턴 종료 버튼이 강조된다. 기물 정보 카드와 기록에 태그의 능력("룩처럼도 이동", "한 턴에 2번 연속 이동")이 나온다.
  - GM 지침: 지속되는 이동 선언에는 moveAs와 moveTimes를 쓰고, 한 번만 특별하게 움직이는 선언은 move 효과로 바로 옮긴다. 값 기준은 프롬프트에 있다(룩·비숍 움직임 1~2턴 DC 11~13·AP 2, 퀸 DC 14~17, 연속 2번 DC 13~15·AP 2, 3번 DC 16~19·AP 3, 오래가면 +3~4).
  - Gemini는 응답 스키마의 속성이 너무 많으면 이유 없이 거부한다(HTTP 400, 판정 스키마에서 311개는 통과, 317개는 거부로 측정). 두 필드를 넣을 자리를 만들려고, 효과가 없는 일반 실패의 연출에서 효과별 연출(beats)을 뺐다. 테스트가 판정과 혼돈 스키마의 속성 수를 311개 이하로 지킨다. 새 필드를 넣을 때는 다른 곳에서 자리를 먼저 만들고 실제 API로 확인한다.
  - 온라인 프로토콜 버전을 4로 올렸다.
- **부서진 조각 (사용자 요청)**
  - 산산조각 난 기물의 조각은 치우지 않고 판 위에 흩어져 남는다. 이전에는 옆자리로 모여 날아가 무더기가 됐다.
  - 조각은 그 기물 자체를 나눈 것이다(사용자 요청: 작은 돌 조각 대신 원래 모양을 지키게). 기물 모양을 높이로 네 띠(20%, 45%, 72%에서 자름)로 자르고, 띠마다 각도로 4, 3, 3, 2쪽으로 나눠 12조각이 된다. 띠마다 금이 다른 각도로 간다. 각 조각은 그 칸에 든 기물 표면의 볼록 껍질(띠끼리 아주 조금 겹침)이라, 합치면 원래 기물 부피의 96~112%로 거의 같은 크기와 무게다. 대부분 장식(액센트) 재질이면 그 색이다.
  - 조각은 Rapier로 터진다: 기물 가운데에서 바깥쪽과 위로(높이 있던 조각일수록 조금 더 높이), 돌면서 날아가 주변 기물(과 이미 흩어진 조각)에 부딪치며 판 위에 멈추고, 판 끝을 넘으면 테이블로 굴러떨어진다(사용자 요청으로 다른 기물과 부딪치게 바꿈). 그 칸에 서 있는 기물(잡은 기물)과는 부딪치지 않는다. 공중에서 부서졌어도 그 아래 땅 칸에서 터진다.
  - 부서지는 모습(사용자 요청: 잔해가 갑자기 생기지 않게): 기물은 일격이 닿을 때까지(공격자가 도착하고 조각 계산이 끝날 때까지) 온전한 모습으로 서 있고, 그 순간 조각들이 기물 안에 있던 바로 그 자리와 방향에서 갈라져 나온다(이전에는 조각이 무작위 방향으로 시작해 기물과 이어지지 않았고, 터지는 시점을 놓쳐 조각이 이미 멈춘 채로 나타날 때가 많았다). 계산이 늦어지면 기물이 그만큼 더 서 있다가 처음부터 재생한다. 부서지는 방식은 두 가지이고 기물마다 정해진다(모든 화면에서 같음): 사방으로 터져 나가기(빠르게 돌며 바깥쪽과 위로), 또는 금이 가며 무너져 내리기(0.2초쯤 금 사이가 벌어진 뒤 조각들이 거의 밀리지 않고 제 무게로 흘러내리며, 위쪽 조각일수록 바깥으로 기울어 넘어짐).
  - 흩어진 조각은 화면의 조각 목록(debris)에 놓인 자리와 재생 중인 기록으로 남는다. 기물이 밀치거나 날아가며 지나가면(romp) 조각도 그 물리에 가벼운 물체로 들어가 밀려나고, 새 자리에 남는다. 기물이 서 있는 칸 밑의 조각은 그 계산에서 뺀다(끼어 튀지 않게). 공중부양 추락과 결투에는 넣지 않는다(방장의 계산과 같게).
  - 판 위나 판 가까이에 놓인 잡힌 기물(끌어다 놓은 것 포함)도 똑같이 기물이 밀치거나 날아가며 지나갈 때 그 물리에 들어가 밀려나고(사용자 요청), 새 자리에 남는다. 들고 있는 것은 이 계산에 넣지 않고 아래 "만지작거리기"의 실시간 물리에서 밀린다. 다른 화면에서 들고 있는 것은 그 화면이 민다.
  - 같은 게임을 본 화면끼리는 같은 계산을 하므로 조각도 같은 자리에 있다. 새로고침하면 터진 직후의 자리로 다시 계산된다(그 뒤 밀린 것과 손으로 옮긴 것은 기억하지 않음).
  - 잡힌 기물 목록에 부서진 땅 칸(at)을 함께 저장하고, 터지는 방향과 회전은 기물 ID로 정하는 씨앗 난수라 모든 화면과 새로고침 뒤에도 같은 자리에 놓인다(새로고침하면 물리를 다시 계산해 마지막 모습만 보여 준다). 앙파상으로 잡혔으면 잡힌 폰이 서 있던 칸이다. 저장에 칸이 없는 예전 게임은 조각 없이 옆자리 모습만 보인다.
  - 조각은 보기용이라 규칙에 영향이 없다. 조각을 톡 누르면 그 아래 칸을 누른 것과 같다(끌면 집어 든다, 아래 "만지작거리기"). 그 칸에 다른 기물이 서도 그대로 있다.
  - 되살리면 흩어진 조각이 저마다 지금 있는 자리에서 차례로 날아올라 되살아날 칸에서 원래 모양대로 맞춰지고(약 1초, 사용자 요청), 맞춰지는 순간 기물로 돌아가 빛난다.
  - 옆자리에는 그 기물의 특징 부분(킹의 십자가, 나이트의 말머리 등)만 누워 있어 무엇을 잃었는지 알아볼 수 있다.
- **행동 쓰기 도움 (사용자 요청)**
  - 입력칸 왼쪽의 깃펜 버튼으로 켜고 끈다. 켜져 있으면 판을 눌러도 기물을 집지 않고, 누른 칸을 입력칸에 이어 쓴다.
  - 누르는 순서는 자유다(사용자 요청: 대상부터 눌러도 됨). 아직 행동하는 기물이 없을 때 내 기물을 누르면 "d2의 폰이 "(조사 이/가는 기물 이름에 맞춤)로 행동하는 기물이 된다. 그 밖의 기물은 "d4의 룩에게 ", 빈 칸은 "e5에 ", 벽이나 구덩이 칸은 "d4의 벽에 "로 이어 쓴다. 예: 상대 폰을 먼저, 내 폰을 다음에 누르면 "d7의 폰에게 d2의 폰이 ". 탑승한 기물 묶음을 누르면 태운 기물로 써진다. 공중의 기물은 "d4^의 퀸이 "처럼 공중 칸으로 쓴다. 직접 친 글자 뒤에도 이어 붙고, 글자 수 제한을 넘으면 넣지 않는다.
  - 켜져 있는 동안 입력칸에서 "~이/가"로 쓰인 칸은 주체(노란 고리), 나머지 칸은 대상(붉은 고리)으로 판에 표시한다. 입력칸 아래에 "기물이나 칸을 누르면 이어 씁니다"가 뜬다.
  - 입력을 보내면 꺼진다. 판정을 기다리는 동안이나 연속 이동 중에는 쓸 수 없다. 나머지(무엇을 하는지)는 플레이어가 직접 쓴다.
- **탄 기물 떨어지기 (사용자 요청)**
  - 태운 기물이 잡히거나 없어지면(일반 수로 잡힘, 제거 효과, 이동 효과로 잡힘, 합에서 짐, 구덩이, 다리가 사라짐, 화상으로 탐) 탄 기물은 함께 잡히지 않고 위에서 굴러떨어진다. 그 뒤는 공중부양이 끝났을 때와 같다: 떨어지는 동안(falling) 다른 명령은 받지 않고, 게임을 진행하는 쪽이 물리로 떨어진 자리를 계산해 land 명령을 보낸다. 가장 많이 겹친 빈 칸에 서고, 구덩이에 떨어지면 파묻히고, 판 밖이나 설 칸이 없으면 산산조각 난다.
  - 떨어지기 시작하는 자리는 태운 기물이 서 있던 칸의 그 기물 꼭대기(지금 그 칸에 선 기물이 더 크면 그 위)다. 공격이 온 칸이 있으면(잡은 기물의 출발 칸, 합 상대) 그 반대쪽으로 밀려 위로 조금 튀며 굴러떨어지고, 없으면 씨앗 난수 방향으로 미끄러진다. 엔진은 FallingPiece에 어떤 기물에 타고 있었는지(rodeOn)와 공격이 온 칸(push)을 남긴다. 물리를 쓸 수 없으면 공격 반대쪽(없으면 판 가운데 쪽)으로 0.75칸 떨어진 자리로 정한다.
  - 킹이 잡혀 게임이 끝나는 경우에는 탄 기물도 그대로 함께 잡힌 것으로 둔다. 공중부양이 끝나 떨어지는 기물에 탄 기물은 지금처럼 함께 떨어진다.
- **탄 기물의 크기와 물리 (사용자 요청)**
  - 탄 기물은 작아지지 않고 원래 크기로 태운 기물 꼭대기에 선다. 올라탈 때도 크기가 바뀌지 않는다.
  - 모든 물리(밀치기와 던지기, 공중부양 추락, 합 결투, 날아가기)에서 탄 기물의 모양을 태운 기물의 몸에 붙인다. 둘은 한 덩어리로 흔들리고 넘어지고 부딪치며, 위가 무거워 더 잘 넘어진다. 화면의 탄 기물은 태운 기물을 그대로 따라간다.
  - 태운 기물의 태그 표시는 탄 기물(과 그 태그 표시) 위로 올린다.
- **탑승 수 제한 없음 (사용자 요청)**
  - 한 기물에 몇 명이든 탈 수 있다. 새로 타는 기물은 맨 위에 쌓이고(탑처럼), 하차 효과는 맨 위의 기물을 내린다. 이미 누군가를 태운 기물이 올라타면 태운 기물째 올라간다.
  - 탑 전체가 아래 기물의 이동 방식으로 함께 움직인다. 합 배율과 기술은 탑에서 가장 좋은 값을 쓴다. 태그는 각자의 것이지만, 편 바꾸기와 불 끄기(탑이 칸을 옮김)는 탑 전체에 미친다. 맨 아래 기물이 잡히면 탄 기물 모두가 굴러떨어진다.
  - 물리에서는 탄 기물 모양을 차례로 쌓아 아래 기물 몸에 붙인다(높을수록 잘 넘어진다). 화면에서는 각 층이 아래층 꼭대기에 서고, 맨 아래 탄 기물이 흔들림을 받으며, 모두의 태그 표시는 탑 꼭대기 위에 한 줄씩 쌓인다. 기물 정보에는 "탑승 중: 폰, 그 위에: 비숍"처럼 차례로 보인다. GM에게는 "(탑승: 폰, 그 위에 비숍)"으로 전달된다.
- **탄 기물의 흔들림 (사용자 요청)**
  - 탄 기물은 태운 기물에 단단히 굳어 있지 않고 발밑을 축으로 살짝 느슨하게 붙어 있다. 태운 기물이 출발하거나 멈추거나 부딪치면 탄 기물이 관성으로 반대쪽으로 기울었다가 스프링처럼 몇 번 흔들리며 바로 선다(강한 충격에 약 7도, 미끄러져 멈출 때 약 4도, 최대 20도). 올라탈 때 내려앉으며 한 번 흔들린다.
  - 모든 움직임(물리 재생, 정해진 이동, 결투)에 똑같이 적용되는 화면 효과다. 물리 계산에서는 지금처럼 탄 기물 모양이 태운 기물 몸에 붙어 있다.
- **만지작거리기 (사용자 요청)**
  - 상대가 수를 두는 동안 심심하지 않게, 옆자리의 잡힌 기물과 판 위의 조각을 손가락(마우스)으로 끌어 옮길 수 있다. 끄는 동안 물건은 판이나 테이블 위로 조금 떠서 따라오고, 카메라는 돌지 않는다.
  - 들고 있는 동안은 물리가 실시간으로 돈다(사용자 요청, liveDrag.ts). 물건은 손가락으로 집은 그 지점에 매달려 중력을 받아 늘어지고 흔들리며, 손가락과는 부드러운 고무줄(스프링, 무게 1당 강성 150, 감쇠비 0.28)로 이어져 늦게 따라오고 지나쳤다 돌아오며 출렁인다. 당기는 힘은 무게의 5배까지라, 길을 막는 것(판의 기물, 조각, 잡힌 기물, 주사위, 상자 벽, 테이블)이 있으면 손가락 쪽으로 버티며 당겨질 뿐 뚫고 가지 않는다(돌아갈 길이 있으면 미끄러져 돌아간다).
  - 놓으면 같은 물리가 이어진다: 휘두르던 그대로 날아가 떨어지고, 가만히 멈추면(또는 5초 뒤) 그 자리에 놓인다. 던진 것은 테이블, 판, 주사위 상자, 판 위의 기물(탄 기물 포함), 흩어진 조각, 다른 잡힌 기물, 주사위에 부딪친다(사용자 요청). 맞은 쪽은 움직이지 않는다(규칙 속 기물이 흔들리지 않게).
  - 손에 든 것도 밀려난다(사용자 요청). 실시간 물리 속 판의 기물들은 매 프레임 화면에 보이는 자리(이동, 밀치기, 던지기, 결투 중이면 그 움직임 그대로)를 따라가는 물체(키네마틱)라서, 기물이 지나가면 들고 있는 것이나 놓아서 날아가는 중인 것을 밀어낸다. 고무줄은 무게의 5배까지만 당기므로 밀려가다가, 기물이 지나가면 다시 손가락 쪽으로 돌아온다. 기물은 밀리지 않는다. 판에 새로 생긴 기물은 그때 들어오고, 없어진 기물은 빠진다.
  - 들고 있는 것은 집은 자리를 지나며 화면(눈)을 마주 보는 면 위에서 손가락을 따라간다(사용자 요청: 바닥에만 붙지 않고 위로 들 수 있게). 손가락을 위로 올리면 공중으로 들리고(최대 높이 5), 내리면 다시 내려온다. 손가락이 그 자리의 바닥보다 아래를 가리키면 바닥(판 위 기물이 있으면 그 꼭대기) 바로 위를 따라 미끄러진다. 마우스 휠로 들고 있는 것을 더 멀리 밀거나 가까이 당길 수 있다. 터치 화면에서는 한 손가락으로 든 채 두 번째 손가락을 화면 위로 밀면 멀어지고 아래로 당기면 가까워진다(1픽셀에 0.012, 사용자 요청). 두 번째 손가락은 다른 것을 집거나 판을 누른 것으로 치지 않고, 캔버스는 터치를 브라우저에 넘기지 않아(touch-action: none) 화면이 확대되거나 밀리지 않는다. 놓을 때의 빠르기는 위아래 방향까지 반영한다(옆으로 휘두르면 살짝 위로 뜬다).
  - 날아가는 중(터지는 중, 밀리는 중, 던져진 중)인 것은 잡을 수 없다. 6픽셀보다 적게 움직이고 떼면 끌기가 아니다(조각은 아래 칸 누르기로 넘어간다).
  - 모든 화면에 실시간으로 보인다(사용자 요청): 들고 있는 동안과 놓은 뒤 멈출 때까지 자세를 1초에 12번까지 다른 화면에 알리고(toy 메시지 hold, 받는 쪽은 부드럽게 따라감), 멈추면 그 자리를 보낸다(drop, 빠르기 0). 받은 화면은 그 자리에 내려놓는다. 방장이 손님끼리 중계하고, 핫시트에서는 보낼 곳이 없다. 다른 화면에서 들고 있는 것은 잡을 수 없다. 규칙과는 상관없고 저장하지 않는다.
- **낙서와 길게 누르기 (사용자 요청)**
  - 게임 화면에서는 글자 선택과 길게 누르기 메뉴(iOS 콜아웃, 안드로이드 메뉴)를 끈다. 화면을 누른 채 그리거나 끌 때 텍스트 선택이 뜨지 않는다. 입력칸과 채팅칸만 글자를 선택할 수 있다.
- **6면 주사위 (사용자 요청)**
  - 게임의 모든 주사위는 6면체(d6)다: 특수 행동 판정, 합, 로비 배경. 1은 대실패, 그 밖에는 DC 이상이면 성공(대성공은 없다). DC는 2~6이고 성공 확률은 DC 2 83%, 3 67%, 4 50%, 5 33%, 6 17%(6이 나와야만)다. GM 지침의 난이도 기준도 이 범위로 옮겼다(그럴듯함 2~3, 대담함 4~5, 결정적 5~6, 합 배율 ×1.2~1.4 DC 4, ×1.5~2.0 DC 5, 영구 +1, 보호막 +1).
  - 3D 주사위는 모서리가 둥근 정육면체(물리는 Rapier roundCuboid)에 진짜 주사위처럼 눈을 찍는다(마주 보는 면의 합 7, 1은 큰 눈). 판정서의 성공 범위는 여섯 칸으로 그린다.
  - 주사위는 위로 튀어 오르며 던져진다(사용자 요청: 세게 굴리기 다음에 바꿈): 가까운 쪽 낮은 곳(높이 0.6~0.8)에서 위로 초속 7.5~9, 앞으로 4~5.5로 빠르게 돌며 튀어 올라 약 1.5(테이블 위 기물 하나 높이쯤) 솟았다가, 상자 가운데를 지나 떨어져 구르고 맞은편 벽에 부딪힌 뒤 멈춘다(부딪힘 약 4번, 1.6~3.2초, 보통 약 2초). 옆으로는 거의 흐르지 않아 옆벽에 높이 부딪히지 않는다. 0.6배 느린 재생으로 구르는 시간을 늘리는 시도는 되돌렸다(사용자 요청). 주사위 시간에 맞춰 수 제한시간에 더해 주는 시간을 특수 행동 5초, 합 8.5초로 조금 늘렸다. 세게 던진 주사위는 벽에 높이 부딪히므로 주사위 상자의 나무 테두리를 높였다(0.4에서 1.0, 상자 단위. 테이블 위로 던진 잡힌 기물이 부딪히는 벽도 같은 높이). 벽에 비스듬히 기대어 멈춘 주사위(위를 향한 면이 분명하지 않음)는 벽 반대쪽으로 살짝 밀어 다시 굴려 평평하게 눕힌다(최대 4번).
  - 합 점수는 반올림한 정수다(위 "합"). 동점이 잦아져 방장이 한 번에 보내는 합 주사위를 20개(9번 동점까지)로 늘렸다.
- **떠돌이 (사용자 요청)**
  - 주체가 있는 혼돈 사건(떠돌이 상인, 의문의 기사, 방랑 마법사 등)은 그 인물을 회색(gray) 기물로 판에 데려온다: 빈 칸에 회색 기물을 spawn하고 같은 칸에 인물의 이름 태그(영구)를 붙인다. 종류는 인물에 맞게(상인·순례자 폰, 기사 나이트, 마법사·성직자 비숍, 거인·용 룩이나 퀸). 회색 기물을 만들거나 회색으로 바꾸는 것은 혼돈 사건만 할 수 있다(특수 행동은 거부).
  - 회색은 누구의 편도 아니고 차례도 없다. 누가 턴을 넘기든 턴이 넘어갈 때마다 방장(권한 쪽)이 회색 기물마다 그 기물의 수 하나를 무작위로 골라 wander 명령으로 움직인다(앞의 떠돌이가 움직인 판을 보고 차례로). 회색 폰은 앞뒤가 없어 아무 방향으로 한 칸 간다. 가는 칸의 기물을 잡을 수 있지만 킹과 보호막·합 장비가 있는 기물은 잡지 않는다. 회색 기물은 체크를 걸지 않는다.
  - 누구든 회색 기물을 보통의 수나 효과로 잡을 수 있고, 잡힐 때까지 판에 머문다. 잡힌 회색 기물은 보통 판에서는 두 편의 줄 사이에, 육각 판에서는 주사위 상자 쪽 옆변의 더 바깥 줄에 놓인다. 회색 기물은 풍화된 돌빛으로 그린다. 기록에는 "🚶 떠돌이가 제멋대로 움직입니다: d4 → e6"이 나온다.
  - GM에게는 혼돈 지침에 "떠돌이" 절이 있고, 판정 지침에는 회색 기물을 만들 수는 없지만 대상으로는 쓸 수 있다는 규칙이 있다. 상황의 기물 목록에 회색이 따로 나오고, 판 그림에서 보통 판은 *, 육각 판은 g로 보인다. 실제 Gemini 점검: "떠돌이 상인"은 회색 폰 + 이름 태그, "방랑 마법사"는 회색 비숍 + 이름 태그(합 배율 1.5)로 데려왔다.
  - 떠돌이 수 제한은 없다. 예전 혼돈 지침의 "판에 이미 떠돌이가 여럿이면 새로 데려오지 말라"는 문장 때문에 한 마리만 있어도 잘 안 나왔다(사용자 제보). 지금은 "떠돌이가 이미 있어도 새로 데려와도 된다(몇이든 제한 없음)"로 바꿨다.
- **주사위 2개 (사용자 요청: 한 개는 확률이 단조로움)**
  - 모든 굴림은 6면 주사위 2개의 합(2~12)이다. 특수 행동은 합이 DC 이상이면 성공하고, 1·1(합 2, 약 3%)은 DC와 상관없이 대실패다. DC는 3~12이고 성공 확률은 DC 3 97%, 4 92%, 5 83%, 6 72%, 7 58%, 8 42%, 9 28%, 10 17%, 11 8%, 12 3%(6·6만)다. 가운데가 잦은 종 모양이라 DC 1의 차이가 가운데에서 크다. 예전 저장의 DC 범위(d20, 주사위 1개)는 불러올 때 3~12로 바뀐다.
  - 방장(권한 쪽)이 주사위 두 개를 굴려 합과 두 눈(dice)을 함께 보내고, 엔진은 눈이 1~6이고 합과 맞는지 확인한다. 기록에는 "주사위 3+4=7 (DC 6)", 결과 표시에는 "3 + 4 = 7"로 보인다. 판정서의 성공 범위는 2~12 열한 칸으로, 칸의 높이는 그 합이 나오는 경우의 수(7이 가장 높음)를 보여 준다.
  - 합(clash)도 양쪽이 각자 주사위 2개를 굴려 (합) × 배율을 반올림한 점수로 겨룬다. 엔진은 한 라운드에 주사위 넷(공격 둘, 방어 둘)을 쓰고, 방장은 한 번에 40개(동점 9번까지)를 보낸다. 합 횟수는 점수 차 7 이상 1합, 4~6 2합, 2~3 3합, 1 4합. 화면에서는 공격 쪽 두 개가 함께 떨어진 뒤 방어 쪽 두 개가 그 사이로 떨어지고, 점수 아래에 "🎲 (1+2) × 0.8 / = 2.4 → 반올림"을 두 줄로 보여 준다.
  - GM 난이도 기준을 2~12로 옮겼다: 그럴듯함 4~6, 대담함 7~9, 결정적 9~11(12는 거의 불가능), 합 배율 ×1.2~1.4 DC 7~8, ×1.5~2.0 DC 9~10, 영구 +2, 보호막 +1, 다리 5~6, 공중부양 내 기물 6~7·상대 9, 이동 능력 룩·비숍 8, 퀸 9~10, 나이트 6~7, 연속 이동 2번 8~9·3번 10~11. 가짜 GM도 같은 눈금으로 바꿨다.
  - 3D 주사위 상자는 한 번에 두 개를 함께 던지고(같은 기록 길이), 쉴 때도 두 개가 나란히 놓여 있다. 로비 배경도 두 개를 굴린다.
- **대성공 없음 (사용자 요청)**
  - 대성공을 없앴다. 결과는 성공, 실패, 대실패(1) 셋이다. 6도 DC와 비교하는 보통 굴림이고(DC가 최대 6이라 언제나 성공), 대성공 효과·서술·연출 칸은 GM 출력과 판정에서 빠졌다. 판정서에는 "1이 나오면 대실패"만 남고, 주사위가 금빛으로 빛나거나 대성공 소리가 나는 일도 없다.
  - 예전 저장의 판례에 남은 대성공은 불러올 때 성공으로 바꾼다.
- **잡힌 기물의 크기 (사용자 요청)**
  - 잡힌 기물은 작아지지 않고 원래 크기 그대로 옆자리로 나간다. 옆자리 간격을 넓혔다(가로 0.86칸, 줄 0.95칸, 한 줄에 7개).
  - 옆으로 튕겨 나가는 방향과 회전은 기물 ID로 정하는 씨앗 난수라 모든 화면에서 같은 자리에 놓인다(드래그를 실시간으로 함께 보려면 놓인 자리가 같아야 하므로).

- **판정 보정: 특기와 정신력 (사용자 요청)**
  - 특수 행동의 주사위 합에 시스템이 보정을 더하고, 화면에 출처와 함께 보인다(판정 카드의 보정 목록, 확률 막대와 성공 확률, 주사위 결과 "5 + 3 +2 = 10", 기록 "주사위 5+3=8 +2 지휘의 깃발 = 10 (DC 9)"). 보정 하나는 ±1~3, 다 더해도 ±4까지다. 1·1은 보정과 상관없이 대실패다. 실패 후 다시 굴릴 때도 같은 보정이 붙는다. 합(결투)에는 쓰지 않는다(합은 배율로 따진다).
  - 특기(skill): 태그에 붙는 능력 {무엇에(about), 보정(bonus)}. GM이 태그를 붙일 때 정한다(지휘의 깃발: 함께 전진하는 행동 +2, 건축가: 지형 만들기 +2, 서투름은 음수). 판정 때 GM은 이번 행동에 맞는 특기 태그의 이름만 고르고(skills), 숫자는 시스템이 그 태그에서 가져온다(GM이 그때그때 숫자를 바꿀 수 없다). 주체와 그 위에 탄 기물의 태그만 친다.
  - 정신력(mind): 태그에 붙는 값 -3~+3. GM이 정신 계열(회유, 매혹, 공포, 설득, 세뇌)이라고 표시한 행동(mental)에서, 대상(target) 기물이 다른 편(회색 포함)이면 그 기물 태그들의 정신력만큼 뺀다(강철 의지 +2 → -2, 겁에 질림 -2 → +2). 내 기물에 거는 행동에는 적용하지 않는다.
  - GM은 DC를 특기와 정신력 없이 정한다(두 번 세지 않도록). 붙이는 값의 기준: +1 DC 6~7·AP 1, +2 DC 8·AP 2, +3 DC 9~10·AP 3, 영구면 DC +2. 판례에도 보정이 남는다.
  - 기물 정보 창의 태그 설명에 특기와 정신력이 나온다. 가짜 GM도 "건축가 특기를 준다", "정신력을 불어넣는다", "회유한다"를 알아듣는다.

- **거리 보정 (사용자 요청: 먼 거리 단검 투척·돌진이 너무 쉬웠음)**
  - 특수 행동의 주체에서 효과가 닿는 가장 먼 칸까지(주체가 move 효과로 달려가면 달려간 거리, 그 뒤의 효과는 도착한 자리에서) 킹 걸음으로 재서, 수단(means)에 따라 시스템이 주사위 합에서 뺀다(`DISTANCE_RULE`, 보정 목록에 "거리 5칸 원거리 -2"처럼 보임).
    - 근접·이동: 2칸부터 2칸마다 -1(최대 -4). 8칸 돌진은 -4.
    - 원거리: 3칸부터 2칸마다 -1(최대 -4). 8칸 단검 투척은 -3.
    - 마법: 4칸부터 3칸마다 -1(최대 -3).
  - GM은 DC에 거리를 넣지 않는다(가까운 곳에서 하는 것처럼 행동 자체의 어려움만, 가로막힘은 +2~3). 가짜 GM의 저격·기절·보호막·불화살 DC에서도 거리 몫을 뺐다. AI 플레이어 프롬프트에도 이 표가 들어가고, "실질 DC"(거리 보정까지 친) 기준으로 선언을 고르게 한다. 보정 합계 상한 ±4는 그대로다.

- **희생 (사용자 요청)**
  - 선언에 내 기물을 바치는 대목이 있으면("e3 폰을 제물로 바쳐…") GM이 그 칸들을 제물(sacrifice)로 적는다. 제물은 선언자 쪽 기물로 주체에서 1칸 이내여야 하고, 킹·주체 자신·누군가를 태운 기물은 안 된다(시스템이 검사).
  - 주사위를 굴리는 순간 제물은 성공과 상관없이 사라진다(대실패여도). 잡힌 기물 자리로 가고, 기록에 "🕯 …이 제물로 바쳐졌습니다", 연출은 사라지는 퇴장(vanish). 판정 카드는 굴리기 전에 이것을 경고한다.
  - 보정: 폰 +1, 나이트·비숍 +2, 룩 +3, 퀸 +4(보정 합계 상한 ±4 안에서). 실패 후 다시 굴리면 제물은 다시 바치지 않고, 바친 보정은 그대로 남는다.
  - 희생이 든 판정은 평소보다 강한 버프를 줄 수 있다: 합 배율 최대 ×2.5(평소 2.0), 특기·정신력 최대 ±4(평소 ±3).
  - 효과는 제물이 사라진 뒤의 판 위에서 일어나는 것으로 검사한다(효과가 제물 칸을 다시 쓰면 거부). 가짜 GM은 "…을 제물로 바쳐/희생시켜"를 알아듣는다.

- **유해 (사용자 요청)**
  - 판 위에서 쓰러진 기물은 모두(잡힘, 제거, 화상, 구덩이, 추락, 희생, 박살·재 포함; 킹 제외) 그 자리(공중이었으면 아래 땅)에 유해를 남긴다. 유해는 그 기물 주인의 턴으로 3턴 동안 남는다(쓰러진 그 턴은 세지 않음, 회색 떠돌이의 유해는 누구의 턴이든 줄어듦). 같은 칸에 여럿이면 가장 새것이 보인다.
  - 판 위에 그 기물 모양의 희미한 윤곽(편마다 다른 빛깔)으로 보이고, 턴이 줄수록 흐려진다. 다른 기물은 그 칸을 자유롭게 지나고 설 수 있다. 윤곽은 움직이지 않는다(배터리: 다시 그리지 않도록).
  - 유해가 남은 칸에 같은 편·같은 종류를 revive하면 판정에 +2(유해) 보정이 붙고, 같은 종류 중 가장 최근 것이 아니라 바로 그 기물이 돌아온다(태그 없이). 되살리면 유해는 사라진다.
  - GM에게는 보드 상태에 "유해" 목록(칸, 편, 종류, 남은 턴)으로 보이고, DC는 유해 없이 정한다.

- **혼란, 행동대장, 원호, 인질 (사용자 요청, 핵심 태그)**
  - 혼란: 주인의 턴이 끝날 때마다 그 기물이 일반 수로 갈 수 있는 빈칸 중 무작위로 비틀거리며 간다(잡지 않음, 킹은 공격받는 칸으로 가지 않음, 갈 칸이 없으면 제자리). 기록 "😵 …이 혼란에 빠져 …로 비틀거립니다".
  - 행동대장 (버프, 사용자 요청): 주인의 턴이 끝날 때마다 행동대장이 자신과 바로 옆(1칸) 같은 편 기물 중에서(킹, 혼란 기물, 움직일 수 없는 기물 제외) 가장 좋은 수 하나를 지휘해 둔다. 고르는 것은 AI 엔진의 보통 수준(2수 앞, 잡기는 끝까지, 합은 승률로)이고, 어떤 수도 그대로 있는 것보다 낫지 않으면 아무도 움직이지 않는다. 잡기도 하지만 킹은 잡지 않는다. 행동대장마다 한 수씩, 한 기물은 같은 턴 끝에 한 번만 움직인다(지휘받아 움직인 행동대장도 제 지휘는 한다). 기절한 행동대장은 지휘하지 못한다. impulse 명령에 지휘한 행동대장의 칸(by)이 붙고, 엔진은 그 기물이 지휘받을 수 있는지(commandable) 검사한다. 기록: "🚩 행동대장 나이트의 지휘로 c4의 룩이 c7로 나섭니다." (예전: 행동대장 자신만 한 수를 더 뒀다.)
  - 둘 다 방장(또는 한 화면) 쪽이 턴이 넘어간 직후, 떠돌이보다 먼저 판 순서대로 정해 보낸다(엔진은 갈 수 있는 칸인지 검사). 누구의 턴도 바뀌지 않는다. 혼란이 행동대장보다 우선한다.
  - 원호: 그 기물 바로 옆(1칸)의 같은 편 기물(킹 제외)이 일반 수, 행동대장의 수, 특수 행동의 move 효과로 잡히려 하면, 원호 기물이 공격자에게 뛰어들어 대신 잡힌다(공격자 쪽으로 몸을 던졌다가 사라지는 모션). 공격자는 제자리에 남고 그 수는 쓴 것으로 친다. 원호 기물에 합 배율이나 보호막이 있으면 공격자와 합을 벌인다(이기면 공격자가 죽음, 보호막은 깨지고 버팀). remove 효과, 화상, 혼돈은 막지 못한다. 킹에는 붙일 수 없다.
  - 인질: 특수 행동의 주체가 바로 옆의 다른 편 기물을 인질로 잡는다(태그에 잡은 기물이 기록됨, 킹은 잡을 수도 잡힐 수도 없음, 혼돈으로는 불가). 인질은 일반 수로 움직이지 못하고 공격하지도 못한다. 잡은 기물이 잡히려 하면 원호와 같은 범위에서 인질이 먼저 대신 죽는다. 잡은 기물이 없어지거나 1칸 밖으로 멀어지면(무엇 때문이든) 바로 풀리고, 지속 턴이 끝나도 풀린다. 효과로 인질을 옮기는 구출은 된다.
  - GM 기준: 혼란 DC 7~8·AP 2, 행동대장 DC 9~10·AP 3(버프 뒤), 원호 DC 7~8·AP 2, 인질 DC 8~9·AP 2~3(1~3턴, 오래가면 +2). 가짜 GM도 네 태그를 알아듣는다.
  - 혼돈에서도 (사용자 요청): 혼돈 프롬프트에 네 태그의 설명과 사건 예(산적이 볼모를 잡음, 기사 서임, 독안개, 충성 맹세)가 들어간다. 인질은 혼돈에 주체가 없으니 tag 효과의 by에 잡는 기물의 칸을 쓴다(인질 바로 옆의 다른 편 기물, 회색 떠돌이도 됨, 킹 제외; 특수 행동에서는 by를 쓰지 않고 주체가 잡는다). 실제 Gemini 점검: 혼란·원호·인질(by)이 나왔다.

- **융합 (사용자 요청, 키메라 겹관)**
  - fuse 효과: 행동하는 기물(주체)이 몸이 되어 바로 옆(1칸)의 기물을 흡수한다. 흡수된 기물은 판에서 사라지고, 그 기물을 알아보게 하는 머리(왕관, 말 머리, 주교관, 성가퀴, 십자가, 공)가 몸 위에 관으로 얹힌다. 관은 흡수한 순서대로 위로 쌓이고(첫 관 0.85배, 그 위는 0.8배씩 작게), 이음매마다 금빛 고리, 관은 원래 편의 색 그대로다. 다섯을 넘으면 금빛 고리로만 쌓는다. 흡수되는 기물은 소용돌이치며 몸 위로 날아가 관이 된다.
  - 킹은 흡수될 수 없고(몸은 됨), 누군가를 태운 기물도 흡수할 수 없다. 상대 기물과 회색 떠돌이도 흡수할 수 있다(GM 기준 DC +2). 횟수 제한은 없다. 이미 융합한 기물을 흡수하면 그 기물의 관까지 통째로 올라간다.
  - 움직임은 몸의 것 그대로(사용자 결정). 대신 융합만으로 합 능력이 생긴다(잡히려 하면 언제나 합): 합 배율은 몸의 기본 배율 + 흡수한 기물 배율의 1/4(흡수할 때마다 누적, 융합 기물을 흡수하면 그 기물의 그때 배율의 1/4). 태그 배율까지 곱한 최종 배율은 ×3.0에서 멈춘다. 두 기물의 태그는 합쳐지고, 같은 태그는 오래가는 쪽이 남는다(탑승·인질은 버림).
  - 융합 기물이 잡히면 안의 기물이 모두 함께 잡힌 기물이 되고 유해도 모두 남긴다. split 효과는 맨 위 관 하나를 떼어 바로 옆 빈 칸에 다시 세운다(남은 관은 하나씩 흡수한 것처럼 배율을 다시 셈).
  - GM 기준(재료 기준): 폰 DC 6·AP 1, 나이트·비숍 DC 8·AP 2, 룩 DC 9·AP 3, 퀸 DC 10·AP 3, 분리 DC 5~6·AP 1. 혼돈으로는 융합하지 않는다. 기물 정보 창에 관 목록과 융합 배율이 나온다. 가짜 GM도 "흡수/융합", "관을 떼어"를 알아듣는다.

## 3인 육각 맵 (사용자 요청)

- **판.** 세 사람이 각자 8칸×4줄 반쪽 판을 하나씩 갖고, 세 반쪽을 육각형으로 붙인다(96칸). 백은 아래, 흑은 오른쪽 위, 적은 왼쪽 위. 반쪽 판은 d|e 사이에서 살짝 꺾인다. 가운데에 삼각형은 없고, 여섯 개의 d4·e4 칸이 가운데 점 하나에서 만난다.
- **줄은 이음매를 곧게 넘는다.** 반쪽 판들은 4번째 줄끼리 맞닿는다. 내 a~d줄은 왼쪽 상대(백이면 적)의 h~e줄로, e~h줄은 오른쪽 상대(백이면 흑)의 d~a줄로 이어진다. 그래서 룩은 내 판의 줄을 올라가 상대 판의 줄을 따라 내려간다. 가로줄은 반쪽 판 안에서만 이어진다.
- **가운데 점의 대각선은 두 갈래(사용자 결정: 후보 ③).** d4(또는 e4)에서 가운데 점을 지나는 대각선은 나머지 두 반쪽 판의 d4(또는 e4)로 갈라져 각각 이어진다. 정반대 칸(색이 바뀜)으로는 가지 않는다. 그래서 비숍은 언제나 제 색 칸에 머문다. 가운데를 지나는 것은 이 대각선 여섯 개뿐이다.
- **나이트**는 "곧게 2칸 후 옆으로 1칸" 또는 "옆으로 1칸 후 곧게 2칸"을 칸 연결을 따라 계산한다. 언제나 다른 색 칸에 내린다.
- **폰**은 제 반쪽 판에서는 안쪽(가운데)으로, 다른 반쪽 판에 들어가면 그 판의 첫 줄 쪽으로 전진한다. 처음 자리(제 판 2번째 줄)에서는 두 칸. 잡기는 앞 대각선(가운데 점을 지나면 두 갈래). 다른 사람의 첫 줄에 닿으면 승격한다.
- **킹이 잡히면 항복(사용자 요청, 이 맵에서만).** 잡힌 쪽은 자기 기물 중 하나를 골라 남기고, 나머지는 모두 잡은 사람에게 지휘권이 넘어간다(색이 바뀐다). 기록에는 "흑의 킹이 백에게 항복했습니다", 이어서 "(남긴 기물)이 망명합니다…"가 나온다. 망명한 기물은 누더기 후드를 뒤집어쓴다: 합 배율 ×1의 장비 태그라서, 잡히려 할 때 언제나 합이 일어나 한 번에 허무하게 죽지 않는다. 항복한 플레이어는 차례를 계속 받아 그 기물로 싸운다. 그 기물마저 잡히면 완전히 탈락한다.
- **망명자의 복귀.** 망명 기물이 다른 사람의 킹을 잡으면 그 기물이 킹으로 승격하고(후드를 벗음), 잡힌 쪽은 위와 같이 그 망명자에게 항복한다.
- **끝.** 판에 킹이 하나만 남으면 그 킹의 플레이어가 이긴다(망명 기물이 남아 있어도).
- **진행 단계.**
  1. 판의 칸 연결과 이동 규칙: `src/engine/hex/geometry.ts` (완료).
  2. 엔진을 맵에 따라 움직이게 (완료): 게임 상태의 map(없으면 보통 판)을 applyCommand가 setBoardMap으로 정하고, 칸 도우미(squares.ts: step, distance, planeOf, squareName "흑e4" 등)와 이동 계산이 그 판을 따른다. 세 번째 색 적, 차례는 백→흑→적(기물이 남은 사람만), 체크는 다른 모든 사람의 공격, 캐슬링·앙파상·승격은 반쪽 판 기준. 떨어지는 기물의 착지 좌표는 판 평면 좌표(보통 판은 칸, 육각 판은 중심에서의 거리).
  3. 항복·망명·복귀와 승리 규칙, 누더기 후드 (완료): 킹이 잡히면(일반 수, 합에서 진 공격 킹, 특수 행동의 합 모두) `kingFell`이 처리한다. 보통 판은 그대로 끝. 육각 판은 잡은 기물이 후드를 쓴 망명자면 킹으로 승격(후드 벗음, crowned 이벤트), 킹이 하나만 남으면 그 편 승리, 아니면 surrendered 이벤트와 GameState.surrender(남은 기물이 없으면 탈락)가 생긴다. surrender가 있는 동안은 항복한 쪽의 exile 명령(남길 칸)만 받는다. 고른 기물(과 그 위에 탄 기물)만 제 편으로 남아 누더기 후드(×1 합 장비, 영구, 머리에 쓴 천 고깔과 밧줄 조형물)를 쓰고, 나머지는 모두 잡은 쪽 색이 된다(exiled 이벤트). 합은 배율이 ×1이어도 합 장비 태그가 있으면 일어난다(hasClashGear). 육각 판에서는 잡힌 킹에 탄 기물도 굴러떨어진다. 차례는 기물이 남은 사람에게만 돌아간다.
  4. 3D 육각 판 (완료): 여섯 모 나무 테두리에 96칸 타일(가운데로 갈수록 넓은 사각형), 각 편의 줄 이름(a~h, 1~4)은 그 편을 향해 쓴다. 테이블이 커지고(반폭 17×11.5), 물리 바닥은 육각 판 슬래브, 주사위 상자는 오른쪽 모서리 너머, 동전 접시는 각자 첫 줄 오른쪽 끝 모서리 너머, 잡힌 기물은 주인 왼쪽의 옆변(아무의 첫 줄도 아닌 변)을 따라 줄지어 놓인다. 나이트는 판 가운데를 본다. 카메라(옆에서·위에서·주사위)는 각자의 자리 뒤에서 본다. 수는 "백e2 백e4", "백e2e4"(같은 반쪽 판) 식으로 친다. 지형(벽·구덩이)은 지금처럼 칸 가운데 한 칸 크기로 그린다(가운데 쪽 넓은 칸에서는 조금 작아 보임). 로비 배경은 보통 판, 대기실 배경은 방에서 고른 판(바꾸면 테이블을 새로 차린다; 둘러보는 카메라는 육각 판에서 더 멀리 돈다). 게임 화면도 판이 바뀌면 장면을 새로 만든다. 물리의 육각 판 바닥은 마주 보는 변을 잇는 상자 셋으로 만든다(하나의 큰 볼록 껍질로 만들었더니 기물이 움직일 때마다 판 위의 다른 기물이 몇 cm씩 떨렸다).
  5. 대기실과 온라인 (완료): 방 규칙의 "판"(보통 체스판 2인 / 육각 판 3인)으로 고른다. 온라인 3인 방은 대기석에서 각자 백·흑·적 자리를 골라 앉고 세 자리가 다 차야 시작한다(처음에는 손님을 흑, 적 순으로 자동으로 앉혔는데, 자리를 고를 수 있게 바꿨다). 한 화면에서 셋이 번갈아 둘 수도 있다. 항복하면 판 위 배너가 "흑의 킹이 백에게 항복했습니다"를 알리고, 항복한 쪽(한 화면이면 누구나) 화면에서 그 편 기물에 고리가 켜져 하나를 누르면 망명한다. 고르는 동안 수 제한시간은 멈춘다. 저장에서 다시 열면 세 자리 모두 기억한다.
  6. GM (완료): 육각 판이면 판정·혼돈 지침에 "3인 육각 판" 절(세 편과 차례, 칸 이름은 반쪽 판 주인 글자를 앞에 붙여 "흑e4", 이음매와 거리, 항복·망명·후드)을 넣고, 상황에는 세 편의 기물과 AP, 반쪽 판마다 그 주인이 보는 방향의 판 그림(칸마다 편 글자 w/b/r와 기물 글자)을 보낸다. 입력 도움과 가짜 GM도 "흑e4" 이름을 읽는다. 실제 Gemini 점검: "백g1의 나이트가 백f3으로 뛰어간다"를 move 백g1→백f3로 판정했고, 백의 차례에 흑·적 기물을 주체로 쓴 선언은 불가능 판정했다.

## AI 플레이어 (사용자 요청)

- **어디서.** 온라인 대기실의 빈 자리에 방장이 "AI 앉히기"를 누르거나, 로비의 "AI와 하기"(한 화면, 흑에 AI)로 시작한다. 한 화면 대기실에서도 자리마다 "AI 앉히기"/"사람으로"를 고를 수 있어, AI끼리만 두는 판도 된다. 끊긴 사람의 자리를 AI가 대신하지는 않는다(사용자 결정). AI 자리는 규칙(`rules.ai`, 색 → {난이도, 특수 행동 빈도})에 있어 저장·이어하기에 그대로 남는다. AI가 앉은 자리에는 사람이 앉을 수 없고, 사람이 앉은 자리에 AI를 앉힐 수 없다. AI 자리는 "채워진 자리"로 쳐서 바로 시작할 수 있다.
- **난이도.** 일반 수는 브라우저 안의 엔진(`src/engine/ai.ts`, 웹 워커에서 계산)이 고른다. 편집증 최소최대(나 대 나머지 모두)에 알파베타, 합은 승률로 나눈 기댓값(우연 노드), 원호의 가로막기와 승격(언제나 퀸)까지 따진다. 판 평가는 기물 값, 융합 관, 태그(합 장비, 기절 등), 자리(중앙, 폰 전진).
  - 쉬움: 1수 앞, 실수가 잦다(점수를 폰 1.2개만큼 흔들고, 25%는 차선의 수).
  - 보통: 상대의 응수까지(2수).
  - 어려움: 3수 앞, 잡기 끝까지 일부 따라감, 드물게 실수(5%).
  - 무아: 최대 4초 동안 깊이를 늘려 가며(반복 심화) 읽고, 잡기는 끝까지 따라가며(정적 탐색), 실수하지 않는다.
- **특수 행동.** 자리마다 끔 / 가끔(기본: AP 2 이상일 때 반쯤) / 자주(AP 1 이상). GM(LLM)이 그 플레이어가 되어 판, AP, 판례, 엔진의 힌트(위험: 공격받는데 지켜 주는 기물이 없는 내 기물, 기회: 공짜로 잡을 수 있는 상대 기물, 노릴 만한 표적: 값지고 가까운 상대 기물과 거리)를 받고 선언 한 줄을 쓴다(`act`). 어려움·무아는 날카롭게, 쉬움·보통은 장난스럽게. 선언에는 예산이 붙는다: 보유 AP를 넘는 비용은 시도할 수 없다는 것, 보통은 DC 8 이하(42% 이상), 어려움·무아는 DC 9 이하로 판정될 행동을 고르라는 것, GM의 DC·AP 기준. 가짜 GM은 틀(위험한 기물에 보호막, 가까운 값진 기물 저격, 기절) 가운데 AP와 DC 한도에 드는 것 중 성공 확률 대비 값이 큰 것을 고르고, 드는 것이 없으면 선언하지 않는다(그 턴은 일반 수만).
- **굴릴지.** 쉬움은 낼 수 있으면 언제나, 보통은 성공 확률 40% 이상이면. 어려움·무아는 판정의 효과를 판에 적용해 보고, 그 뒤 자기 수와 상대의 응수까지(2수, 잡기는 끝까지 2수 더) 읽은 값을 지금 그대로 둘 때와 비교한다(성공, 그냥 실패, 대실패 역효과를 확률로 섞음). 그래서 잡는 효과만이 아니라 공격하려는 기물을 기절시키거나 도망칠 수 없는 기물에 보호막을 두르는 것도 값이 있다. 판 평가에는 태그 값도 들어간다(기절은 그 기물 값의 15%를 깎음, 인질 30%, 혼란·화상 10%; 다른 기물처럼 움직이기·연속 이동·특기·정신력·공중부양·원호·행동대장은 조금 더함). 기대 이득이 AP 값(AP 1 = 폰 0.25개, AP가 2 이상 남으면 그 절반)보다 크면 굴린다. 다시 굴리기도 같은 기준. 이 계산은 웹 워커에서 한다. 굴리지 않기로 한 선언은 바로 다시 하지 않고, 그 뒤 자기 두 턴은 특수 행동을 쉰다. 온라인 대기실에서 API GM이면 "AI의 특수 행동도 GM API를 씁니다"를 알린다.
- **합 이해.** 일반 수의 탐색은 합을 우연 노드로 계산한다(양쪽 배율로 이길 확률, 지면 공격한 기물을 잃음, 보호막은 깨지기만 함, 원호의 가로막기). 특수 행동의 가치 계산도 효과 안의 합(이동 효과로 합 장비가 있는 칸에 들어가기)을 그 시점 배율의 승률로 이긴 경우와 진 경우 둘 다 읽어 섞는다(전에는 공격 쪽이 이긴다고 가정했다). 선언을 쓰는 LLM에게는 합 규칙(배율 계산, 지면 공격 기물이 잡힘, 원거리 제거에는 합이 없음, 특수 행동 뒤 같은 턴에 일반 수 가능)을 알려 주고, 엔진 힌트에 "합 표적"(합이 일어나는 잡기와 내 기물별 승률; 이런 기물은 "기회"로 세지 않음)과 "합 계획"(1턴짜리 배율 ×1.4/×2를 주면 승률이 얼마가 되는지, 배율 판정 DC 8/9 성공까지 합친 확률)을 넣는다. 가짜 GM도 지금은 지지만 검술(×1.5)이 있으면 해 볼 만해지는 잡기가 있으면 "검술을 익힌다"를 후보로 둔다.
- **화면.** AI는 연출(이동, 주사위, 합, 낙하)이 끝난 뒤 조금(약 1초) 있다가 둔다. 그동안 위쪽 차례 표시가 "🤖 보통 · 생각 중…"으로 깜빡이고, 입력창에도 "🤖 흑 AI가 생각 중…"이 나온다. AI의 판정 창에는 굴리기 버튼 대신 "🤖 흑 AI가 굴릴지 정하는 중입니다…". 한 화면에서는 AI의 차례·판정·망명을 사람이 대신할 수 없고, 카메라는 사람 자리 쪽에 머문다. 육각 판에서 항복한 AI는 가장 센 기물을 남긴다. AI는 채팅하지 않는다.
- **실행.** 방장(또는 한 화면) 브라우저의 권한자(`authority.ts`)가 AI 차례마다 엔진을 돌리고 일반 명령(move, declare, attempt/cancel, exile, endTurn)을 그 색으로 보낸다. 손님은 결과만 받는다.

## AI 관전 (사용자 요청)

- **시작.** 로비의 "AI끼리 보기"는 백(보통)과 흑(어려움) 자리에 AI가 앉은 한 화면 대기실을 연다(특수 행동은 가끔). 난이도와 판을 바꿀 수 있고, 모든 자리가 AI인 대기실에서 육각 판을 고르면 적 자리에도 AI(보통)가 앉는다. 온라인 방도 방장이 모든 자리에 AI를 앉히면 된다: 방장은 대기석에 있어도 시작할 수 있고, 다 같이 관전석에서 채팅·낙서하며 본다. "관전하는 판"은 따로 저장된 표시가 아니라 모든 자리가 AI인 판이다(`isAiOnly`).
- **일시정지와 속도.** 관전 막대의 ⏸ 멈춤/▶ 계속, 느리게/보통/빠르게(온라인이면 방장만). 속도는 연출(이동, 주사위, 합, 낙하)이 끝난 뒤 쉬는 시간만 바꾼다: 느리게 2.4초, 보통 0.9초(연출과 겹침), 빠르게 0.12초. 멈추면 진행 중인 행동만 마치고 다음 수를 두지 않으며 수 제한시간도 멈춘다. 모든 자리가 AI인 판이 아니면 멈춤과 속도는 의미가 없다(보통 속도, 멈춤 풀림).
- **카메라.** 판 주위를 2분에 한 바퀴 천천히 돌고, 수가 둬지면 그 칸 쪽으로 잠깐 다가갔다가(목표점을 35%만큼) 가운데로 돌아온다. 손으로 카메라를 움직이면 멈추고, 놓은 뒤 6초가 지나면 다시 돈다. 주사위·합 시점은 그대로 쓰고, 그동안은 돌지 않는다.
- **판세 막대.** 엔진 점수로 각 편의 몫을 보여 준다. 2인 판은 진행 중인 잡기를 끝까지 따라간 점수(정적 탐색)를 부드러운 곡선으로(룩 하나 앞서면 약 80%), 육각 판은 각 편의 재료 값으로 세 칸. 킹이 없는 편은 0, 끝난 판은 이긴 편이 전부. 모든 자리가 AI인 판에서만 보인다(사람이 두는 판에서는 힌트가 되므로). LLM 해설은 없다.
- **전적과 한 판 더.** 관전 막대에 이번 관전의 전적("보통 1 : 2 어려움", 같은 난이도면 A·B)이 나온다. 승리 화면의 "한 판 더 (자리 바꿔서)"는 대기실을 거치지 않고 바로 새 판을 시작하며, AI들이 한 자리씩 옮겨 앉는다(2인: 백↔흑, 육각: 백→흑→적→백). 전적은 AI를 따라간다. 대기실에서 AI 구성을 바꾸면 새 전적. 로비로 나가면 사라진다.
- **저장.** 모든 자리가 AI인 판은 자동 저장하지 않는다(저장 칸이 하나뿐이라 내 게임을 덮어쓰지 않게).
- **끼어들기(한 화면만).** 위쪽 차례 표시를 누르면 자리 메뉴가 열린다: AI 자리는 난이도를 바꾸거나 "내가 이어 두기", 사람 자리는 "AI에게 맡기기"(보통, 가끔). 넘겨받는 순간 AI가 생각하던 것은 버리고, 그 판은 일반 게임이 된다(판세 막대·멈춤·속도가 사라지고, 저장이 시작된다). 다시 모든 편을 AI에게 맡기면 관전으로 돌아간다. 관전 중에는 입력창과 턴 종료 버튼을 숨기고, AI의 판정 창은 뒤의 버튼(멈춤, 자리 메뉴)을 막지 않는다.

## 건물 (사용자 요청)

- **무엇.** 건물은 효과가 붙은 벽이다(`TerrainCell.building`: 종류, 이름, 무엇에(about), 보너스). 들어가거나 지나가지 못하는 것, 나이트가 뛰어넘는 것, 사다리로 넘는 것, clearTerrain으로 부수는 것은 벽과 같다. 지형 칸 수 상한(12칸)에 같이 센다.
- **종류.** 정해진 셋: 대포(cannon, 원거리 공격), 교회(church, 기물 되살리기·소생), 대장간(forge, 칼이나 무기를 만들거나 얻기). 이름과 about을 비우면 시스템이 채우고, 3D 모양(조형물 프리셋 cannon, chapel, forge)도 준다. 그 밖에는 자유 건물(custom): GM이 이름(12자)과 about(30자)을 직접 정하고 prop으로 모양을 만든다. 보너스는 +1~+3, 기본 +2.
- **효과.** 주체가 건물에서 1칸 안에 있고 행동이 그 건물의 about에 맞으면, GM이 판정의 buildings 목록에 그 건물 칸을 적고 시스템이 보너스를 주사위에 더한다(판정 보정의 한 종류 'building', 보정 목록에 "건물 대장간 +2"; 다른 보정과 합쳐 ±4 상한). GM은 DC에 넣지 않는다. 누구의 건물이든 쓸 수 있다. 엔진은 지목된 칸에 건물이 있고 주체에서 1칸 안인지 검사하고(`checkBuildings`), 굴릴 때 건물이 이미 없어졌으면 보너스도 없다.
- **짓기.** 특수 행동으로 빈 칸에 짓는다(terrain wall + building, GM 기준 DC 8~9·AP 3, 보통 영구). 혼돈 사건으로도 생긴다(순례자들이 교회를 세움 등). 기록: "🏰 e3에 대장간이 세워졌습니다 (영구)".
- **화면.** 건물 위에 "대장간 무기 +2"처럼 이름, 하는 일, 보너스 이름표가 뜬다(자유 건물은 about을 8자까지). 남은 턴이 있으면 따로 표시.
- **GM과 AI.** 판정 지침에 "건물" 절, 상황 설명의 지형 목록에 건물 정보(이름, about, 보너스, "1칸 안의 기물이 쓰면 buildings에 이 칸"), 혼돈 지침에 건물 효과와 사건 예. AI 플레이어에게는 건물 규칙과 엔진 힌트("건물: c3 대포(원거리 공격 +2): 옆의 내 기물 c2 폰")를 준다. 가짜 GM은 "…에 대포/교회/대장간을 짓는다"를 알아듣고, 주체 옆의 건물이 선언에 맞으면(대포: 쏘기·던지기, 교회: 되살리기, 대장간: 검·무기) 판정에 지목한다.
- **실제 Gemini 점검.** 대포 옆 폰의 사격에 대포(+2, 거리 -2와 함께), 교회 옆 되살리기에 교회(+2), 대장간 옆 검술에 대장간(+2)을 지목했고, 건물과 상관없는 사격에는 지목하지 않았다. "h3에 대장간을 짓는다"는 DC 8·AP 3의 forge 건물로 판정했다.

## 게임 설명 책 (사용자 요청)

- **어디서.** 첫 화면(로비) 메뉴의 "📖 이 게임이 매우 전략적인 이유". 누르면 메뉴가 사라지고, 투어하던 카메라가 테이블 앞쪽 왼편(주사위 상자 바깥)에 놓인 가죽 장정 책으로 날아가며, 도착할 즈음 표지가 넘어가 펼쳐진다. "✕ 책 덮기"(또는 Esc)로 덮으면 펼친 장이 위에서부터 차례로 덮이고 카메라는 투어로 돌아간다.
- **책.** 앞뒤 표지 사이에 종이 세 장(앞뒤 6쪽)과 표지 안쪽 두 쪽, 모두 8쪽: 차례 / AP / 판정과 주사위 / 보정 / 합 / 판정을 잘 받는 법 / 태그 사전 / 건물과 혼돈. 쪽은 캔버스에 그린 낡은 종이(테두리, 쪽 번호)이고, 글자는 쪽에 맞는 가장 큰 크기로 자동으로 맞춘다. 앞표지는 금박 제목과 나이트 문장.
- **물리.** 장마다 책등을 축으로 한 각도와 속도가 있어 중력(세워질수록 덜, 기울면 그쪽으로), 공기 저항, 바닥에 닿을 때의 작은 튐을 받는다. 종이는 휜다: 넘어가는 동안 속도에 밀려 뒤처지고, 들려 있을 때 처진다(스프링으로 출렁임). 장은 앞 장을 앞지르지 못한다(표지 먼저, 그다음 장 순서). 표지는 휘지 않는다. 계산은 실제 시간을 잘게 나눠 해서 느린 화면에서도 같은 속도로 넘어간다.
- **넘기기.** "다음 ▶ / ◀ 이전"(또는 ←/→), 쪽을 톡 치기(그쪽으로 넘어감), 손으로 끌기. 넓은 화면은 두 쪽을 함께 보이고 손가락 위치를 책 위의 점으로 따라간다. 좁은(세로) 화면은 한 쪽씩 크게 보이고, "다음"은 왼쪽 쪽에서 오른쪽 쪽으로 카메라를 옮긴 뒤 장을 넘기며, 손으로는 화면 폭의 70%를 쓸면 한 장이 넘어간다. 손을 떼면 기운 쪽으로 살짝 튕겨 준다. 손이 책 밖으로 나가도 끌기는 이어진다. 아래 표시는 인쇄된 쪽 번호("차례 · 1쪽", "4쪽" …).
- **게임 테이블에도.** 게임 중에도 같은 책이 테이블에 놓여 있다: 보통 판은 보는 사람 자리의 앞쪽 왼편(주사위 상자 바깥, 로비와 같은 자리를 그 편으로 돌린 곳), 육각 판은 자기 변 바로 바깥 가운데. 보는 편(온라인은 내 자리, 한 화면은 둘 차례인 편)이 바뀌면 책도 그 편으로 옮겨 가되, 펼쳐 둔 동안에는 덮을 때까지 그대로 둔다. 카메라 연출은 없다(사용자 결정): 표지를 손으로 끌거나 톡 치면 펼쳐지고, 장을 끌거나 톡 쳐서 넘기며, 표지를 다시 덮으면 닫힌다. 책장을 잡고 있는 동안에는 테이블 카메라가 돌지 않는다. 가까이 보려면 평소처럼 카메라를 돌리고 당긴다. 로비 책도 표지를 손으로 덮으면 닫힌다.
- **선명한 글씨.** 쪽은 1.5배 해상도로 그리고, 본문은 책의 명조(Hahmlet) 굵은 520 무게에 짙은 먹색으로 쓴다(가는 고딕은 3D 종이 위에서 흐려 보였다). 책이 펼쳐져 있는 동안은 화면을 더 촘촘히 그린다(로비는 기기 화면 그대로 최대 3배, 게임 중에는 최대 2배; 평소 터치 기기는 1.5배).
- **낮은 가로 화면.** 높이 600px 미만의 가로 화면(가로로 든 휴대폰)에서는 한 쪽씩 크게 보이고, 위아래 여백 없이 책을 화면에 꽉 채우며, 이전/다음 버튼은 오른쪽 가장자리에 세로로 놓인다(아래 안내 문구는 숨김).
