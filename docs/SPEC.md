# 아주 전략적인 체스 (Very Tactical Chess) — 스펙

## Problem Statement

일반 체스는 정해진 규칙 안에서만 기물을 움직일 수 있다. 친구와 체스를 두면서 "폰을 나이트에 태워서 돌진시킨다", "비숍이 성벽을 세운다" 같은 상상력을 발휘하고 싶어도, 그걸 공정하게 판정해 줄 사람이 없다. 사람이 GM을 맡으면 한 명은 플레이할 수 없고, 판정이 편향되거나 매번 달라진다. 또 이런 게임을 친구와 온라인으로 즐기려면 서버 비용이 드는데, 취미 프로젝트로는 감당하기 어렵다.

## Solution

두 플레이어가 각자 브라우저에서 접속해 체스를 두되, 규칙에 없는 기상천외한 행동을 채팅으로 입력하면 LLM GM이 판정해 주는 TRPG형 체스 게임이다.

- 정상적인 체스 수는 게임 엔진이 즉시 처리한다.
- 규칙 밖의 행동은 "특수 행동"으로 LLM GM에게 전달된다. GM이 해석, 난이도(DC), 비용(AP)을 제시하면, 플레이어가 시도 여부를 정하고 d20 주사위로 성패가 갈린다.
- 결과는 엔진이 검증 가능한 정해진 효과(이동, 제거, 태그 부여, 변환, 생성)로만 보드에 반영되어 보드 상태가 흔들리지 않는다.
- 킹을 잡으면 승리한다. 원턴킬 방지 규칙으로 특수 행동을 이용한 즉사 콤보를 막는다.
- 체스판, 기물, 주사위는 3D로 표현하고, 주사위는 실제로 구르는 연출과 함께 결과가 나온다.
- 서버 없이 P2P(방장 브라우저가 권위)로 동작하고, 정적 사이트로 무료 배포한다. LLM API 키는 방장 본인 것을 쓴다(BYOK).

## User Stories

### 방 만들기와 접속

1. As a 방장, I want 새 게임 방을 만들고 방 코드/초대 링크를 받기, so that 친구를 쉽게 초대할 수 있다
2. As a 방장, I want 방을 만들 때 GM으로 쓸 LLM 제공자(Claude, OpenAI, Gemini)와 모델을 고르기, so that 내가 가진 키와 선호에 맞출 수 있다
3. As a 방장, I want 내 API 키를 입력하기, so that 운영자 서버 없이 GM 판정을 쓸 수 있다
4. As a 방장, I want 내 API 키가 상대 브라우저로 절대 전송되지 않기, so that 키가 유출되지 않는다
5. As a 방장, I want 무료로 쓸 수 있는 키(Gemini 무료 등급) 안내를 보기, so that 비용 없이 시작할 수 있다
6. As a 참가자, I want 초대 링크나 방 코드로 방에 들어가기, so that 별도 가입 없이 바로 플레이할 수 있다
7. As a 참가자, I want 내 API 키 없이도 플레이하기, so that 방장만 키를 준비하면 된다
8. As a 플레이어, I want P2P 연결이 실패했을 때 그 사실과 대안(핫시트 모드)을 안내받기, so that 막히지 않고 게임할 수 있다
9. As a 플레이어, I want 한 화면에서 번갈아 두는 핫시트 모드로 플레이하기, so that 네트워크 문제가 있거나 옆에 앉아 있을 때도 게임할 수 있다
10. As a 플레이어, I want 내가 백인지 흑인지 명확히 알기, so that 헷갈리지 않는다

### 일반 체스 수

11. As a 플레이어, I want 보드에서 기물을 클릭/드래그하거나 "e2e4", "나이트 f3" 같은 텍스트로 일반 수를 두기, so that 편한 방식으로 둘 수 있다
12. As a 플레이어, I want 일반 수가 LLM을 거치지 않고 즉시 처리되기, so that 빠르고 API 비용이 들지 않는다
13. As a 플레이어, I want 캐슬링, 앙파상, 프로모션이 기존 체스대로 동작하기, so that 체스 지식을 그대로 쓸 수 있다
14. As a 플레이어, I want 내 킹을 공격받는 위치에 두는 수(자살 수 포함)도 둘 수 있되 경고를 보기, so that 킹 잡기 승리 규칙과 일관되면서 실수를 알아챌 수 있다
15. As a 플레이어, I want 일반 수를 두면 내 턴이 끝나기, so that 턴 흐름이 명확하다
16. As a 플레이어, I want 기절한 기물은 일반 수로도 움직일 수 없기, so that 특수 행동의 효과가 실제로 의미가 있다
17. As a 플레이어, I want 다른 기물에 탑승한 기물이 태운 기물과 함께 움직이기, so that "폰을 나이트에 태우기" 같은 효과가 보드에서 유지된다
18. As a 플레이어, I want 보호막이 있는 기물이 한 번 잡혀도 버티기, so that 방어형 특수 행동이 의미가 있다

### 특수 행동

19. As a 플레이어, I want 채팅창에 규칙 밖의 행동을 자연어(한국어)로 입력하기, so that 상상력을 발휘해 플레이할 수 있다
20. As a 플레이어, I want 입력이 일반 수로 해석되면 엔진이 처리하고, 아니면 특수 행동으로 GM에게 가기, so that 따로 모드를 바꿀 필요가 없다
21. As a 플레이어, I want 특수 행동 입력 후 GM이 제시한 해석, DC, AP 비용을 먼저 보기, so that 확률을 보고 도박할지 정할 수 있다
22. As a 플레이어, I want 제시를 보고 "시도" 또는 "취소"를 고르기, so that 마음에 들지 않으면 AP를 쓰지 않고 물러날 수 있다
23. As a 플레이어, I want 취소한 행동은 AP를 쓴 것으로 치지 않기, so that 확인 단계에서 불이익이 없다
24. As a 플레이어, I want AP가 부족한 행동은 시도할 수 없기, so that 자원 규칙이 지켜진다
25. As a 플레이어, I want 주사위 굴림과 결과(성공/실패/대성공/대실패)를 화면에서 보기, so that 판정이 투명하고 긴장감이 있다
26. As a 플레이어, I want 주사위는 LLM이 아니라 게임이 굴리기, so that 결과가 조작되지 않는다
27. As a 플레이어, I want 성공한 행동의 효과가 보드에 즉시 반영되기, so that 결과를 바로 확인할 수 있다
28. As a 플레이어, I want 대성공(20) 시 더 좋은 결과를 받기, so that 극적인 순간이 생긴다
29. As a 플레이어, I want 일반 실패 시에는 AP만 잃기, so that 시도 자체가 지나치게 위험하지 않다
30. As a 플레이어, I want 대실패(1) 시에만 GM이 역효과(예: 내 기물 기절)를 주기, so that 무모한 시도에 적당한 위험이 있다
31. As a 플레이어, I want 각 판정에 GM의 서술이 붙기, so that TRPG처럼 이야기가 만들어진다
32. As a 플레이어, I want AP가 남아 있는 동안 한 턴에 특수 행동을 여러 번 하기, so that 콤보를 짤 수 있다
33. As a 플레이어, I want 특수 행동이 실패해도 내 턴이 계속되기, so that AP가 남으면 다른 시도를 할 수 있다
34. As a 플레이어, I want 특수 행동을 시도한 뒤 일반 수 없이 "턴 종료" 버튼으로 턴을 끝내기, so that 특수 행동만 하고 끝낼 수 있다
35. As a 플레이어, I want 특수 행동으로 기물에 태그(기절, 탑승, 보호막, 자유 태그)를 부여하기, so that 다양한 전술이 가능하다
36. As a 플레이어, I want 태그의 남은 지속 턴을 보기, so that 언제 효과가 끝나는지 알 수 있다
37. As a 플레이어, I want 지속 시간이 끝난 태그가 자동으로 사라지기, so that 보드 상태가 깔끔하게 유지된다
38. As a 플레이어, I want 킹에게 기절 같은 태그를 거는 특수 행동을 하기, so that 킹을 묶는 전략을 쓸 수 있다
39. As a 플레이어, I want 특수 행동으로는 킹을 직접 제거할 수 없기, so that 승부가 항상 체스 수로 난다

46. As a 개발자, I want AP 시작값, 증가량, 최대치, 비용 범위, DC 범위를 설정 파일에서 조정하기, so that 플레이 테스트로 밸런스를 맞출 수 있다

## Implementation Decisions

### 아키텍처

- **P2P, 방장 권위.** 방장 브라우저가 게임 엔진을 실행하고 보드 상태, 주사위, LLM 호출을 모두 담당한다. 참가자 브라우저는 입력을 방장에게 보내고 방장이 브로드캐스트하는 상태를 표시만 한다. 방장이 조작할 가능성은 친구끼리 플레이하는 범위에서 허용한다.
- **연결:** PeerJS의 무료 공개 시그널링 서버로 WebRTC 연결을 맺는다. 방 코드는 방장의 피어 ID에서 만든다. 연결이 실패하는 환경을 위해 같은 엔진을 쓰는 로컬 핫시트 모드를 제공한다.
- **배포:** 정적 사이트를 GitHub Pages에 무료로 배포한다. 운영 서버는 없다.
- **스택:** TypeScript, Vite, React. 3D는 react-three-fiber + drei, 주사위 물리 연출은 Rapier. 체스 로직은 직접 구현한다(chess.js 같은 라이브러리는 태그·탑승 상태를 표현할 수 없음).
- **나중의 전환:** 출시를 검토하게 되면 엔진을 서버(예: Cloudflare Workers + Durable Objects)로 옮겨 서버 권위 구조로 바꾼다. 이를 위해 엔진은 처음부터 순수 모듈로 만든다.

### 모듈

1. **게임 엔진 (핵심, 순수 모듈).** 네트워크, UI, LLM, 난수 소스에 의존하지 않는다. 인터페이스는 대략 "현재 상태 + 명령 → 새 상태 + 이벤트 목록 (또는 거부 사유)" 형태의 리듀서다.
   - 상태: 보드(칸별 기물, 기물 ID, 색, 종류, 태그 목록), 현재 턴과 턴 번호, 각 플레이어의 AP, 이번 턴 AP 사용 여부, 일반 수 사용 여부, 캐슬링·앙파상 권리, 판례 목록, 게임 종료 여부와 승자.
   - 명령: 일반 수, 특수 행동 제안 수신(GM 결과), 특수 행동 시도(주사위 값을 입력으로 받음), 특수 행동 취소, 턴 종료.
   - 주사위 값은 엔진 밖에서 생성해 명령에 담아 넘긴다. 그래야 엔진이 결정적이고 테스트 가능하다.
   - 담당 규칙: 합법 수 판정(태그 반영), 효과 검증과 적용, AP 증감과 이월, 태그 지속 시간 감소와 만료, 체크 판정, 원턴킬 방지, 자동 턴 종료, 킹 잡기 승리.
2. **효과 어휘 (엔진의 일부).** GM이 반환할 수 있는 효과는 다음으로 한정한다.
   - 이동(기물 ID, 목적지)
   - 제거(기물 ID). 대상이 킹이면 거부.
   - 태그 부여/해제(기물 ID, 태그 이름, 선택적 지속 턴 수). 지속 턴이 없으면 영구.
   - 변환(기물 ID, 새 종류)
   - 생성(칸, 색, 종류)
   - 핵심 태그는 엔진이 의미를 강제한다: `기절`(이동 불가, 체크를 걸지 못함), `탑승`(운반 기물 ID 참조, 함께 이동, 체크 판정은 운반 기물의 이동 방식), `보호막`(첫 번째 잡힘을 무효화하고 소멸). 그 밖의 태그는 자유 태그로 엔진은 저장만 하고 GM 문맥으로 넘긴다.
3. **GM 모듈 (LLM 판정).**
   - 입력: 플레이어의 행동 선언(최대 200자), 현재 보드 상태 요약, 해당 플레이어의 AP, 판례 목록, 효과 어휘 정의와 규칙.
   - 출력(구조화 JSON): 행동 해석, 가능 여부, DC(설정 범위 내, 기본 5~25), AP 비용(기본 1~3), 성공 시 효과 목록, 대성공 시 효과 목록, 대실패 시 역효과 목록, 서술 문구.
   - 시스템 프롬프트는 플레이어 입력을 "행동 선언" 데이터로만 다루게 하고, 판타지 전장 해설자 말투의 한국어 서술을 요구한다.
   - GM 출력은 엔진이 스키마와 규칙으로 다시 검증한다. 어긋나면 거부하고, AP를 차감하지 않고, 플레이어에게 안내한다.
   - 확인 단계(해석·DC·비용 제시)에서 LLM 호출 1회가 일어난다. 시도할 때는 이미 받은 결과를 쓰므로 추가 호출 없이 주사위만 굴린다. 서술을 결과에 맞게 다시 생성할지는 구현 중에 정한다.
4. **LLM 제공자 어댑터.** 공통 인터페이스(프롬프트 + 출력 스키마 → 구조화 결과) 뒤에 Claude, OpenAI, Gemini 어댑터를 둔다. 모두 방장 브라우저에서 직접 호출하며, 브라우저 직접 호출에 필요한 각 제공자의 설정은 구현 시 공식 문서로 확인한다. 로컬 모델(Ollama 등)은 나중에 추가한다.
5. **세션/네트워크 모듈.** PeerJS 연결, 방장↔참가자 메시지 프로토콜(참가자 → 방장: 명령 요청, 방장 → 참가자: 상태 스냅샷과 이벤트), 재접속 처리, 방장 이탈 시 일시정지. 핫시트 모드는 같은 인터페이스를 로컬로 구현한다.
6. **저장 모듈.** 방장 브라우저 로컬 저장소에 매 턴 상태 스냅샷을 저장하고 복원한다. API 키는 저장하지 않는다(세션 동안 메모리에만 유지).
7. **3D 장면.** 체스판, 기물, 주사위를 react-three-fiber로 그린다. 엔진 상태를 받아 표시만 하며, 게임 규칙을 알지 않는다.
   - 기물은 처음에는 코드로 만든 회전체 모양의 클래식 체스 말로 시작하고, 나중에 3D 모델 파일로 바꿀 수 있게 기물 표현을 한 곳에 모은다.
   - 태그 표현: 탑승은 운반 기물 위에 올라탄 모습, 기절은 머리 위에 도는 별, 보호막은 반투명 구체, 자유 태그는 이름표. 화려한 이펙트는 범위 밖.
   - 카메라: 각 플레이어 진영 쪽 비스듬한 시점에서 시작. 회전과 확대 가능. 시점 초기화 버튼과 위에서 내려다보는 시점 전환 버튼 제공.
   - 주사위: **결과는 엔진이 먼저 정하고(방장의 난수), 화면은 그 숫자가 나오도록 연출만 한다.** Rapier 물리로 구르게 한 뒤 원하는 면이 위로 오게 맞춘다. 물리 시뮬레이션 결과를 판정에 쓰지 않으므로 방장과 참가자 화면의 결과가 항상 같다. 연출이 끝난 뒤 결과와 효과를 표시하며, 건너뛰기 버튼을 제공한다.
8. **UI (2D 오버레이).** 3D 장면 위에 겹친 일반 화면. 체크 표시, 채팅 로그(행동, 판정 제시, 주사위, 서술), AP 표시, 턴 표시, 시도/취소 확인 창, 턴 종료 버튼, 판례 목록, 방 만들기/참가 화면(제공자·모델·키 입력, 무료 키 안내).

### 턴 규칙 (정밀 정의)

- 턴이 시작되면 해당 플레이어의 AP가 +1 된다(최대 5). 게임 시작 시 AP는 0이다.
- 턴 중에 특수 행동은 AP가 허용하는 만큼 몇 번이든 시도할 수 있다. 실패해도 턴은 계속된다.
- 일반 수는 턴당 최대 1회이며 두면 턴이 끝난다. 일반 수 없이 "턴 종료"로 끝낼 수도 있지만, 그 턴에 특수 행동을 하나 이상 시도했어야 한다(아무것도 하지 않고 넘기기는 불가).
- 특수 행동 흐름: 입력 → GM 제시(해석, DC, 비용) → 시도 또는 취소. 취소는 AP 사용으로 치지 않는다. 시도하면 AP를 차감하고 d20을 굴린다.
  - 20: 대성공 효과 적용
  - DC 이상: 성공 효과 적용
  - DC 미만: 효과 없음 (AP만 소모)
  - 1: 대실패 역효과 적용
- **원턴킬 방지.**
  - 이번 턴에 특수 행동을 한 번이라도 시도했으면 이번 턴에는 어떤 방법으로도 킹을 잡을 수 없다.
  - 특수 행동 결과 처리 후(성공, 실패, 대실패 역효과 모두) 상대 킹이 현재 플레이어의 기물에게 공격받고 있으면 "체크!"를 표시하고 턴을 자동으로 종료한다. 남은 AP는 이월된다.
  - 턴 시작 시점에 이미 상대 킹을 공격할 수 있으면, 특수 행동 없이 일반 수로 잡아 승리할 수 있다. 특수 행동을 쓰면 위 자동 종료 규칙이 적용된다.
  - 이전 턴에 만든 효과를 이용해 AP 없이 킹을 잡는 것은 허용된다.
- 킹은 특수 행동의 효과로 제거할 수 없다. 태그 부여는 가능하다.
- 체크 판정은 핵심 태그를 반영한다. 기절한 기물은 체크를 걸지 못하고, 탑승한 기물은 운반 기물의 이동 방식으로 판정한다. 보호막이 있는 킹도 공격받으면 체크로 표시한다.
- 자신의 킹을 공격받게 두는 수도 허용하며 경고만 표시한다.
- 태그 지속 시간은 턴이 넘어갈 때 감소하고 0이 되면 제거된다. 정확한 감소 시점(누구의 턴 기준인지)은 구현 시 정하고 설정 파일에 명시한다.

### 판례

- 특수 행동 판정(시도된 것)을 "행동 요약, DC, 비용, 결과"로 기록한다.
- 이후 GM 호출 때 판례 목록을 함께 넘겨서 비슷한 행동을 비슷하게 판정하게 한다.
- 판례는 게임 단위로만 유지한다.

### 설정 값 (기본값, 조정 가능)

- AP: 시작 0, 턴당 +1, 최대 5
- 특수 행동 비용: 1~3 AP
- DC 범위: 5~25
- 특수 행동 입력 최대 길이: 200자

## Testing Decisions

- **좋은 테스트란:** 외부 동작만 검증한다. 테스트는 "상태 + 명령 → 결과 상태/이벤트/거부"만 보고, 엔진 내부 함수 구조에 의존하지 않는다.
- **주요 테스트 경계(seam): 게임 엔진의 리듀서 인터페이스 하나.** 주사위 값과 GM 결과를 명령의 입력으로 넘기므로, LLM이나 네트워크 없이 모든 규칙을 결정적으로 테스트할 수 있다. 대상:
  - 일반 체스 규칙(캐슬링, 앙파상, 프로모션, 자살 수 허용, 킹 잡기 승리)
  - 핵심 태그(기절 이동 불가, 탑승 동반 이동, 보호막 1회 무효화)와 지속 시간 만료
  - AP 증감, 최대치, 이월, 부족 시 시도 불가, 취소 시 미차감
  - 주사위 구간별 결과(1, DC 미만, DC 이상, 20)
  - 원턴킬 방지 전 경우(AP 사용 턴의 킹 잡기 거부, 특수 행동 후 체크 자동 종료, 턴 시작부터 체크인 경우, 태그를 반영한 체크 판정)
  - GM 출력 검증(허용 목록 밖 효과, 킹 제거 효과, 범위 밖 DC/비용 거부)
- **보조 경계: GM 모듈.** LLM 어댑터를 가짜로 바꿔서, 프롬프트 구성(판례 포함, 입력 길이 제한)과 응답 파싱·검증을 테스트한다. 실제 API 호출은 자동 테스트에 포함하지 않는다.
- 3D 장면은 규칙을 갖지 않으므로 자동 테스트 대상이 아니다. 단, 주사위의 "원하는 숫자를 위로 맞추는" 계산은 순수 함수로 분리해서 테스트한다.
- 네트워크(PeerJS)와 UI는 자동 테스트 대상에서 제외하고 수동으로 확인한다. 엔진이 분리되어 있어서 핫시트 모드로 대부분을 확인할 수 있다.
- **기존 사례:** 저장소에 코드가 아직 없어서 참고할 테스트는 없다. 테스트 러너는 Vite와 잘 맞는 Vitest를 쓴다.

## Out of Scope

- 서버 권위 구조, 계정, 매치메이킹, 공개 서비스 출시 (출시를 검토할 때 별도 스펙)
- 운영자 API 키 제공 (BYOK만 지원)
- 상대 플레이어의 리액션/카운터 (턴은 순수하게 번갈아 진행)
- 로컬 LLM(Ollama 등) 지원
- 방장 조작 방지 (P2P 방장 권위 구조의 알려진 한계)
- 관전, 리플레이, 시간 제한(체스 클락)
- 한국어 외 언어 지원
- 외부 3D 기물 모델, 화려한 효과 이펙트(불꽃, 폭발 등)
- AI 상대(컴퓨터 플레이어)

## Further Notes

- **서버비 0원 조건:** 서버비는 들지 않지만 GM 판정마다 LLM API 사용료가 나간다. 이 비용은 방장의 키로 청구된다.
- **P2P 연결 한계:** 일부 네트워크(회사, 학교 등)에서는 TURN 서버 없이 연결이 실패할 수 있다. 핫시트 모드가 대안이다.
- **밸런스:** AP 수치, DC/비용 범위는 첫 플레이 테스트 후 조정할 것을 전제로 한다.
- **구현 중 결정된 사항:**
  - 캐슬링은 체크를 무시한다(체크 상태에서, 공격받는 칸을 지나, 공격받는 칸으로 모두 가능). 자살 수를 허용하는 규칙과 일관되게 하기 위함. (#2)
  - GM은 한 번의 호출에서 성공 서술과 실패 서술을 모두 돌려준다. 주사위 후 추가 호출은 없다. (#4)
  - 게임 시작 시 AP는 둘 다 0이고 백의 첫 턴이 시작되므로 백은 1 AP로 시작한다. (#4)
  - GM 효과는 칸 이름(예: "e4")으로 대상을 가리키고, 목록 순서대로 적용된다. 이동 효과로 상대 기물(킹 제외)이 있는 칸에 가면 그 기물을 잡는다. (#4)
  - Claude GM 기본 모델은 Claude Opus 5.5이고, GM 설정에서 Sonnet 5.5나 Haiku 5.5로 바꿀 수 있다. 판정 깊이(effort)는 플레이어가 기다리는 시간을 줄이려고 기본 "low"로 둔다. (#5)

  - 3D 주사위는 Rapier로 실제 물리 시뮬레이션을 먼저 돌려 궤적을 기록한 뒤 재생한다. 엔진이 정한 숫자가 위로 오도록, 충돌 모양은 그대로 두고 숫자가 그려진 겉면만 정이십면체의 대칭 회전 중 하나로 돌려 씌운다. 그래서 움직임과 멈춘 자세는 물리 그대로이고 숫자만 엔진 결과와 같다. 각 브라우저가 따로 굴리므로 굴러가는 모습은 다를 수 있지만 나오는 숫자는 항상 같다. (#12)

  - 수 제한시간은 내 차례에만 흐르고, GM이 판정하거나 혼돈을 만드는 동안에는 멈춘다. 특수 행동을 시도하면 주사위 연출 시간으로 4초를 더 준다. 시간이 다 되면 벌칙만큼 AP를 잃고(가진 만큼만), 대기 중인 판정은 취소되며, 턴이 넘어간다. 시계는 방장 쪽에서만 돌고 다른 사람에게는 남은 시간을 보내 각자 화면에서 줄어든다. 마지막 5초에는 똑딱 소리가 난다.
  - 혼돈: 턴이 시작될 때마다 정한 확률로 방장의 GM이 기상천외한 사건(제목, 해설, 효과 1~3개)을 만든다. 효과는 특수 행동과 같은 어휘에 "편 바꾸기(convert)"가 더해졌다("백의 폰은 사실 흑의 스파이였습니다!"). AP와 주사위 없이 적용되고, 킹은 건드릴 수 없으며, 사건 뒤에 어느 쪽 킹이든 공격받게 되면 사건 전체가 취소된다(공짜로 킹을 잡는 일이 없게). GM 오류나 규칙 위반이면 "혼돈이 일어나려다 잠잠해졌습니다"라고만 알리고 넘어간다. 일어난 혼돈은 기록되어 이후 판정과 혼돈 때 GM에게 전달된다. 화면에는 큰 배너와 효과음으로 알린다.
  - 편 바꾸기(convert) 효과는 일반 특수 행동에도 쓸 수 있다(매수, 배신 등). 탄 기물도 함께 편을 바꾼다.
  - 낙서 모드(방 규칙, 기본 켬): 게임 화면의 "✏️ 낙서"를 누르면 도구 막대가 열리고, 그동안은 시점이 고정되고 기물을 고를 수 없다. 펜(가늘게/굵게, 6가지 색)으로 보드나 테이블 위에 끌어서 그리고, 메모 도구로 짧은 글(40자)을 원하는 곳에 놓는다(놓은 사람 쪽에서 바로 읽히는 방향). 지우개로 내 낙서를 누르면 지워지고(방장과 핫시트는 누구 것이든), ↶로 내 마지막 낙서를, 아래 버튼으로 내 낙서 전부(방장은 전부)를 지운다. 낙서는 방 안 모두(관전자 포함)가 함께 보고 그리며, 저장되지 않고 새 게임을 시작하면 지워진다. 방 전체 낙서는 최대 300개, 한 획은 최대 400점이다.
